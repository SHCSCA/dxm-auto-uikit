# 用户交付使用说明 - 2026-06-24

## 交付结论

当前可交付给真实用户验收的是 **DXM 半托管自动化工作台**，用于在真实店小秘浏览器中完成受控两段式只保存流程：登录店小秘、从数据采集认领商品到采集箱、进入采集箱编辑保存、按编辑页分区补齐配置、创建单商品只保存任务、在执行浏览器观察真实浏览器和日志、核对保存成功且未发布的证据。

当前可用范围是 **数据采集认领 + 采集箱编辑保存 + 受控单商品只保存**。最终动作只保存，不发布。当前不可交付的是店小秘真实批量保存、无人值守写入和任何发布动作。

阅读顺序：

1. 普通用户先看“Windows 单窗口启动”和“真实单商品只保存操作流程”。
2. 需要判断交付证据时，再看后文“验收人附录”。
3. 开发自检和源码包检查不属于普通用户日常操作路径。

## Windows 单窗口启动

### 推荐入口：DXM Agent Console 桌面版

真实用户优先使用桌面版。桌面版会在一个 Agent 控制台窗口内启动本机后端并加载工作台，不需要分别打开后端和前端两个控制台窗口。

当前给用户的免安装 EXE：

```text
D:\Desktop\DXM-Agent-Console-免安装版\DXM-Agent-Console-Portable-0.1.0.exe
outputs\desktop-build\DXM-Agent-Console-Portable-0.1.0.exe
```

2026-06-24 当前分支 packaged/portable smoke 已通过，文件 SHA-256：

```text
96348443EE8A5D47664002958D53ECBE647ACEC034DF0CC5B24402B1E8232AA3
```

仓库内同源构建产物：

```text
outputs\desktop-build\win-unpacked\DXM-Agent-Console.exe
outputs\desktop-build\DXM-Agent-Console-Portable-0.1.0.exe
```

目录版必须保留整个文件夹和 `resources` 目录，不能只复制 exe 文件。portable 首次启动会解包 Electron 与 Python 运行时，`%TEMP%` 所在磁盘建议至少保留 1GB 可用空间；空间不足时会出现启动即退出、没有日志的现象。

源码开发态可用：

```bat
scripts\start-desktop.bat
```

桌面版运行日志：

```text
%APPDATA%\DXM Agent Console\data\desktop-main.log
%APPDATA%\DXM Agent Console\data\backend.log
```

packaged exe 验收命令：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verify-desktop-package.ps1
```

该命令会启动 `outputs\desktop-build\win-unpacked\DXM-Agent-Console.exe`，确认桌面日志出现后端启动和前端加载记录。若桌面版启动失败，会显示启动失败窗口，并提示查看 `AppData\Roaming\DXM Agent Console\data\desktop-main.log`。

### 源码备用入口：start-mvp 单窗口启动器

1. 打开解压后的项目根目录，也就是包含 `README.md` 的目录；下文记为 `<PROJECT_ROOT>`。
2. 运行环境检查：

```bat
cd /d <PROJECT_ROOT>
scripts\start-mvp.bat --check
```

3. 检查通过后启动：

```bat
scripts\start-mvp.bat
```

4. 保留当前启动器窗口。后端和前端会由这个窗口托管，后端/前端新日志会带 `[backend]`、`[frontend]` 前缀实时显示在同一个窗口里；健康检查通过后会自动打开工作台页面。如果 5173 端口被占用，启动器会使用附近空闲端口，实际地址以启动器输出和 `data\start-mvp.log` 为准。
5. 默认浏览器地址：

```text
http://127.0.0.1:5173
```

6. 停止服务：关闭当前启动器窗口，或在启动器窗口按 `Ctrl+C`。脚本退出时会尽力停止后端和前端子进程树。

启动器会自动接管 8000 端口上由本项目旧版本启动的 `uvicorn src.main:app` 后端，以避免工作台连接旧代码；若 8000 被未知进程占用，启动器会失败退出并要求人工处理。不要在真实任务 running/paused 时重复启动新的 `start-mvp.bat`，否则会中断旧后端会话；先在工作台确认没有运行中的真实任务，或先正常关闭旧启动器窗口。

启动日志：

- `data\start-mvp.log`：启动器、端口和健康检查。
- `data\backend.log`：后端 API、任务和运行时控制。
- `data\frontend.log`：前端 Vite 服务。
- `data\npm-install.log`：首次依赖安装。

## 真实单商品只保存操作流程

按以下顺序执行。不要跳过页面检查和人工确认，也不要用开发自检批次代替真实验收。

### 第 1 步：打开真实店小秘登录页并登录

1. 启动工作台后先看“操作首页”的下一步提示，再进入“账号登录”。
2. 在“登录真实店小秘”区域点击“打开真实登录页”。
3. 在页面内登录表单输入店小秘账号和密码。桌面版可勾选“记住账号密码”，凭据会做本机加密保存，并由 Electron `safeStorage` 加密；取消勾选或点击“清除已记住账号”会清除本机保存的密码。凭据不写入编辑页配置、不上传云端。
4. 系统会打开可见的独立浏览器并访问 `https://www.dianxiaomi.com/`，用户可直接输入验证码、查看错误并手动调整。
5. 在这个真实店小秘浏览器窗口中完成人工登录、验证码、二次确认或账号选择。
6. 回到工作台确认“DXM 登录”状态变为已登录或 `login_success` / `logged_in`。

如果需要观察真实浏览器会话状态、日志和网络响应，再进入“真实浏览器”。“打开执行浏览器”用于任务执行观察；真实保存仍受只读页面检查和人工确认保护。

### 第 2 步：在编辑页配置补齐店小秘编辑页分区

进入“编辑页配置”，按页面分区填写。每个分区保存后，“本次任务实际取值预览”会显示最终取值来源。

需要逐项核对的分区：

- 店铺与任务基础：店铺、执行模式、绑定类目、认领标记。
- 类目与标题：目标类目、类目关键词、DXM 类目 ID、标题覆盖和标题策略。
- SKU / 价格 / 库存：SKU 编码、库存、JIT 库存、SKU 规则和变种策略。
- 价格策略：商品价、供货价、价格来源、倍率或固定价。
- 图片与素材：EU 外包装图、营销图策略、主图策略和本地素材目录。
- 包装物流：重量、长宽高、物流属性、运费模板和服务模板。
- 合规 / 海关：报关品名、材质、用途、品牌和合规声明。
- 半托管：商品价、JIT 库存、是否原包装、半托管长宽高、货号策略和条码策略。
- 店小秘引用模板：属性信息、描述、运费、服务、欧盟责任人、制造商、合规模板和半托管模板。

保存规则：

- 有当前任务时，优先用“仅本次任务使用”，避免影响后续任务。
- 需要沉淀为店铺或类目默认值时，再用“保存为店铺模板”。
- 配置预检显示“配置还不能启动真实保存”时，必须先补齐缺失项；系统不会进入真实保存。

### 第 3 步：在商品与任务创建单商品只保存任务

1. 进入“商品与任务”。
2. 在“创建真实任务”区域选择店铺。当前受控真实写入门禁要求店铺为 `Dang Kang`。
3. 在执行模式中选择“单商品只保存”。不要选择开发自检批次作为真实交付依据。
4. 在商品队列中只选择要核验的真实商品。当前可交付范围是单商品受控保存；如列表里有多个商品，按受控口径分批创建，不把它解释为无人值守批量。
5. 点击“创建真实任务”，然后在任务列表中选中刚创建的任务。

如果“启动”按钮显示以下状态，按提示处理：

- `配置未完成，禁止启动`：回到“编辑页配置”补齐缺失字段。
- `只读检查未通过，禁止启动`：查看只读失败诊断并重新运行只读复验。
- `人工确认未完成，禁止启动`：只读检查或人工批准未满足，不能绕过。
- `未发布，禁止启动`：当前模式不是已放行的单商品只保存。

### 第 4 步：人工批准并启动单商品只保存

当任务满足配置预检、只读页面检查通过和单商品只保存模式后，页面会显示“申请并启动单商品只保存”。

1. 点击“申请并启动单商品只保存”。
2. 在表单中输入批准人标识，例如 `ops-owner`。
3. 系统会向后端申请服务端批准令牌，并用确认口令 `CONFIRM_DXM_SAVE_ONLY` 启动任务。
4. 后端只允许通过任务 runner 证据链执行真实写入；直接调用店小秘写入端点会被 403 阻断。

这一步只批准受控单商品只保存。它不批准认领、批量保存、无人值守批量或发布。

### 第 5 步：在真实浏览器观察真实浏览器和日志

任务启动后会自动进入“真实浏览器”。默认只需要观察主操作区、真实浏览器窗口左上角黑色中文任务进度窗和实时日志；账号密码、会话管理、高级浏览器控制、运行维护和自动操作轨迹是折叠区，只有需要人工接管、选择器操作或排查时再展开。

- “真实浏览器”：显示独立店小秘浏览器的会话状态、当前 URL、浏览器数据目录、证据路径和发布隔离状态；真实店小秘页面左上角会显示黑色中文进度窗，例如开始任务、填写标题、选择分类、点击保存。控制台不把本地截图渲染成实时画面，截图只作为报告证据路径保存。
- “自动操作轨迹”：折叠在辅助面板中，显示点击、填写、上传、等待、保存等动作。
- “网络响应”：关注保存接口响应，尤其是 `popChoiceProduct/add.json`。
- “实时日志中心”：切换“后端 / 前端 / 启动器 / 任务 / 浏览器 Agent”，可搜索 `保存`、`error`、`add.json`。
- “执行步骤明细”：确认步骤按状态机推进，没有跳过只读页面检查和人工确认。

如果真实浏览器停留在登录页、验证码页或页面加载异常，先人工处理登录态或查看只读诊断；不要手动点击发布、提交发布、保存并发布等按钮。

### 第 6 步：核对只保存不发布的结果

任务完成后进入“结果与问题”，核对：

- 保存接口返回成功，例如 `code=0`。
- 报告中的 `published=false`。
- 有未发布证明、截图、保存响应或 HAR/network 证据。
- 保存隔离摘要显示发布动作未开放或发布隔离通过。
- “结果与问题”里没有阻断当前任务的未处理异常。

只有同时满足“保存成功”和“未发布”时，才把这次 `single_save` 视为通过。不能把这次结果扩大解释为批量保存、无人值守运行或发布放行。

## 用户可做的事

- 通过 `scripts\start-mvp.bat` 单窗口启动工作台。
- 在真实店小秘浏览器中完成人工登录。
- 查看当前任务、商品、模板、证据、报告和异常。
- 在“编辑页配置”按店小秘编辑页分区填写并保存配置。
- 在“商品与任务”创建单商品只保存真实任务。
- 在“真实浏览器”观察真实浏览器会话状态、网络响应、页面黑色中文进度窗和实时日志；需要时展开会话管理、高级浏览器控制和自动操作轨迹。
- 查看只读页面检查、人工确认和保存证据状态。
- 在只读页面检查未通过时查看只读失败诊断。
- 在“结果与问题”或最终自检报告的 `L2 Allowlist Review Candidates` 段落查看只读依赖人工评审清单。
- 复核真实保存为何被阻断。
- 在“结果与问题”查看交付自检摘要、报告路径、真实写入阻断状态和当前证据。

## 用户不能做的事

- 不能在当前状态启动真实认领、批量保存、批量无人值守或任何发布动作。
- 不能把单商品只保存可用扩大解释为批量保存、自动发布或无人值守运行可用。
- 不能把“创建本地 dry_run 演示批次”当成真实交付结果。
- 不能手动绕过工作台去调用店小秘写入端点。
- 不能绕过真实双目标只读页面检查。
- 不能把 mock 或 fallback 数据当成真实页面通过证据。
- 不能宣称当前版本已经完成真实无人值守保存交付。

## 放行前置

真实保存交付必须同时满足：

- `data_acquisition` 与 `draft_box` 两个真实目标同轮次通过；两份证据必须共享同一个 `evidence_binding.run_id`、`script_sha256`、`git_head` 和 session fingerprint。
- 只读页面检查证据无写请求、非只读请求、禁用 URL、WebSocket 或登录态异常。
- 服务端校验人工批准令牌。
- 单商品只保存产生保存成功、未发布证明、截图和 network/HAR 保存响应证据。

## 验收人快速判定清单

自动化工作台验收通过需要同时看到：

- `Local workbench check: PASS`
- `Browser QA: PASS`
- `Final report center QA: PASS`

真实写入是否可启动要另外看门禁状态：

- `Real DXM write readiness: BLOCKED`：当前不能启动真实保存，通常是 L2 真实只读证据过期、未过或 L3 未批准；这不代表工作台本地功能失败。
- `Real DXM write readiness: READY`：只代表受控单商品只保存路径具备当前有效证据。
- `okScope=local_workbench_only`：工作台可交付，真实写入未放行。
- `okScope=local_workbench_and_controlled_single_save_ready`：工作台可交付，且受控单商品只保存当前可按门禁启动。
- `batchUnattendedPublishAllowed=false`

这组结果不代表真实 DXM 批量写入、无人值守或发布可用；真实单商品只保存仍只能按只读页面检查、人工批准和保存证据链启动。

源码包交付通过还需要：

- `Source package check: PASS`
- 使用 `scripts\final-delivery-check.bat -RequireCleanWorktree` 生成报告。
- 报告里的 Git HEAD 与当前交付源码一致。

自动化、管理摘要或人工复核都不能只看 `ok: true`。`ok: true` 必须和 `okScope`、`realDxmMutationAllowed`、`Real DXM write readiness` 一起解释。以 `outputs/final-delivery-check/final-delivery-check.json` 的 `gitHead` 字段为准判断报告是否对应当前交付源码。

## 验收人附录：自检命令

推荐给验收人的自动化工作台一键自检：

```bat
scripts\final-delivery-check.bat
```

它会依次执行启动前检查、后端全量测试、前端生产构建、L1 selector replay、`git diff --check` 和浏览器 QA，并生成：

- `outputs/final-delivery-check/final-delivery-check.md`
- `outputs/final-delivery-check/final-delivery-check.json`

报告顶部会分别显示“自动化工作台自检结果”和“真实 DXM 写入放行状态”。浏览器 QA 会临时启动隔离的当前源码后端和前端预览服务，避免误测 8000/5173 上的旧进程；不需要先手动启动 `scripts\start-mvp.bat`。也可以按下面的单项命令逐步检查。

当前版本的源码包验收成功标准是：`Local workbench check: PASS`、`Browser QA: PASS`、`Final report center QA: PASS`、`Source package check: PASS`，并按 L2/L3 门禁计算 `Real DXM write readiness`。当前没有新鲜 L2/L3 放行时，应使用 `-ExpectedRealDxmWriteReadiness BLOCKED`；这代表工作台可交付、真实写入不可启动。只有重新取得同一 run-id 的 L2 双目标真实只读证据，并补齐 L3 单商品只保存证据链后，才允许用 `READY` 验收，且只代表受控 `single_save`。

## L2 allowlist 人工评审包

最终自检报告会在 `L2 Allowlist Review Candidates` 段落列出可能属于只读启动依赖的 GET/XHR 请求。“结果与问题”也会在只读失败诊断里展示同一类候选请求，便于操作者不离开页面就知道下一步要评审哪些路径。

这些候选项只代表“需要人工评审”，不是放行结论：

- `review_only=True`
- `allowlist_applied=False`
- 不自动放行只读页面检查或真实保存

人工评审时只能考虑显式、最小、可审计的只读依赖；不能放行 POST、PUT、PATCH、DELETE、WebSocket、EventSource，也不能放行命中 `save/publish/claim/remark/note` 等禁用关键词的 URL。不能为了让报告全绿而绕过只读页面检查或人工确认。

每次运行最终自检会同时生成可填写的人工评审模板：

- `outputs/final-delivery-check/l2-allowlist-review-template.md`
- `outputs/final-delivery-check/l2-allowlist-review-template.json`

最终自检报告和报告中心会同时展示这两份模板的 `sha256` 哈希。评审、归档或转交模板时，应核对路径、Git HEAD 和哈希都对应同一次 `final-delivery-check` 输出；如果模板被填写或改动，必须保留填写后的新文件和新哈希，不能用已改动模板冒充原始自检模板。

评审记录至少要填写 `reviewer`、`reviewed_at`、`decision`、`rationale`、`approved_scope`、`residual_risk`。批准项还必须写明最小化范围、到期时间或后续复核策略，并在代码/配置变更后重新跑同一批真实 L2 双目标；模板本身不是 L2 通过证明。

如果要验收源码发布包，再运行：

```bat
scripts\final-delivery-check.bat -RequireCleanWorktree
```

该模式要求 git 工作区干净；当前仍在开发中时会显示 `Source package check: FAIL`，不影响你查看本地工作台自检是否通过。

## 常见失败定位

- `scripts\start-mvp.bat --check` 失败：先看 `data\start-mvp.log`；缺 Python/Node/npm/curl 时按日志提示补环境，前端依赖安装失败看 `data\npm-install.log`。
- 启动提示 8000 端口占用：若占用者是本项目旧后端，正式启动会自动接管；若占用者是未知进程，启动器会失败退出。真实任务 running/paused 时不要重复启动新工作台，先完成或停止旧任务。
- 启动最后显示 `STARTED_WITH_WARNINGS`：服务窗口已打开，但后端或前端健康检查暂未响应；先看 `data\backend.log` / `data\frontend.log`，不要把它当成完全启动成功。
- 浏览器 QA 失败：先看 `outputs/final-delivery-check\browser-workbench-qa.stdout.log` / `.stderr.log`，再看 `outputs/final-delivery-check\browser-checks\qa-browser-check.json` 的失败 assertion；本机必须安装 Chrome 或 Edge。
- 真实店小秘浏览器已经登录，但工作台仍显示“登录未通过”或“浏览器连接异常”：保持真实浏览器窗口打开，点击“验证码完成后检测登录状态”。2026-06-22 版本会优先复用可见登录浏览器的状态；如果仍失败，查看状态详情里的真实错误，再关闭残留窗口后重开免安装版。
- 最终自检没有生成 `final-delivery-check.md`：先看控制台最后一条错误，再运行 `scripts\start-mvp.bat --check` 定位缺失依赖。
- `Source package check: FAIL`：只在 `-RequireCleanWorktree` 模式下代表工作区不干净，运行 `git status --short` 查看未提交改动；不表示真实 DXM 可以写入。
- `Real DXM write readiness: BLOCKED`：表示当次验收没有真实写入放行；不要为了让报告“全绿”去绕过 L2/L3 门禁。
