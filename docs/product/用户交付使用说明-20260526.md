# 用户交付使用说明

更新时间：2026-07-22

## 交付结论

DXM Agent Console 用真实可见浏览器处理店小秘商品箱中已经存在的商品，按确认模板编辑并只保存、不发布。

当前产品路径：

```text
登录店小秘 -> 商品箱选择现有商品 -> 确认配置 -> 人工批准 -> 保存 -> 独立确认未发布
```

支持两种受控范围：

- 单商品 `single_save`；
- 一次批准、严格串行的 `controlled_edit_batch`。

当前版本没有认领环节，也不会通过链接新建商品。旧 `batch_save`、无人值守调度和所有发布动作不可交付。

## Windows 启动

### 推荐：免安装桌面版

只使用从当前交付 Git HEAD 新构建、已记录 SHA-256 且通过 packaged/portable smoke 的 EXE。旧包必须从交付目录删除，不能与新包并存。

默认构建位置：

```text
outputs\desktop-build\DXM-Agent-Console-Portable-0.1.0.exe
```

桌面日志：

```text
%APPDATA%\DXM Agent Console\data\desktop-main.log
%APPDATA%\DXM Agent Console\data\backend.log
```

### 源码备用入口

```bat
cd /d <PROJECT_ROOT>
scripts\start-mvp.bat --check
scripts\start-mvp.bat
```

保留启动器窗口；关闭窗口或按 `Ctrl+C` 会停止服务。

## 单商品只保存

### 1. 登录真实店小秘

在“店小秘登录”点击打开真实登录页。验证码由用户在可见浏览器中完成；不要并行打开多个受控登录会话。

### 2. 确认模板

在“模板中心”核对：

- 店铺、类目和标题；
- SKU、价格、库存和价格策略；
- 图片与素材；
- 包装、物流、合规和海关；
- 半托管货品与变种；
- 店小秘引用模板。

required 项缺失时任务不会进入保存。

### 3. 从商品箱选择商品

进入“商品箱编辑保存”，选择一个已经存在且已验证的商品。系统会冻结：

- 商品 ID、标题和状态；
- 店铺 ID/名称；
- 来源 URL；
- 精确页面目标；
- 商品箱观察时间和证据文件；
- 完整快照 fingerprint。

商品、店铺、来源、目标或证据漂移时必须重新选择并创建新任务。

### 4. 批准并启动

商品箱 L2、配置和发布隔离都通过后，填写批准人并确认 `CONFIRM_DXM_SAVE_ONLY`。批准由服务端签发短时租约，并在真实保存启动时原子消费。

批准不开放发布，不开放其他商品，也不能复用于新任务。

### 5. 观察执行

在“真实浏览器”查看当前页面、HUD、步骤和关键日志。不要手工点击保存或发布按钮；如果页面被人工切换导致目标漂移，系统会停止。

### 6. 核对结果

“结果与问题”必须同时显示：

- 精确保存 endpoint 的成功回包；
- 页面新的保存成功状态；
- 保存截图与 hash；
- 保存后独立采集的未发布截图与 hash；
- 同商品/店铺/来源绑定；
- `published=false` 且无发布网络信号；
- task/job/report/exception 状态一致。

报告字段 `published=false` 本身不是独立未发布证明。

## 受控整批

1. 在商品箱冻结当前可见范围与顺序。
2. 核对店铺级模板 bundle 和商品数量。
3. 一次批准并启动批次。
4. 系统按冻结顺序全局单并发执行；每个商品派发前获得 60 秒一次性 grant。
5. 每个商品分别产出保存回包和未发布证据。
6. 保存前零写入失败可以隔离；保存已派发或结果不确定时整个批次停止。
7. `UNKNOWN` 必须人工对账，禁止自动重试。

单商品验收不能替代整批验收。

## 用户可以做的事

- 登录真实店小秘并处理验证码。
- 维护店铺模板和任务覆盖配置。
- 从商品箱选择现有商品。
- 明确批准一次单商品保存或一个冻结批次。
- 查看真实浏览器、日志、证据和问题。
- 对 `UNKNOWN`、身份漂移和页面异常进行人工复核。

## 用户不能做的事

- 通过系统认领、采集或新建商品。
- 启动旧 `batch_save` 或无人值守调度。
- 发布、立即发布、继续发布、保存并发布或移入待发布。
- 复用旧批准、旧 L2、旧 EXE 或其他商品的证据。
- 在 `UNKNOWN` 或派发结果不确定后自动重试。

## L2 放行前置

L2 只探测真实商品箱 `draft_box`，必须满足：

- 用户明确批准真实只读探测；
- cookie/session 有效且不在登录页；
- 目标和最终 URL 都在商品箱路径；
- `evidence_binding.target_set=["draft_box"]`；
- run id、脚本 hash、Git HEAD 和 session fingerprint 完整一致；
- JSON/Markdown/截图/DOM 与 hash 完整；
- 写入、非只读、拦截、禁词和 WebSocket 计数全为 0；
- 证据在时效窗口内。

L2 通过仍不等于保存批准。

## 验收人快速清单

- [ ] 使用的是新建空目录中的全新 portable，旧 EXE 已删除。
- [ ] EXE SHA-256 与交付记录一致。
- [ ] 报告 Git HEAD、运行后端 identity 和 portable build identity 一致。
- [ ] 后端全量、前端 build、桌面 build 和脚本契约通过。
- [ ] 商品箱 L2 为当前、真实且 binding 完整。
- [ ] `singleSaveAcceptance.passed=true`、`missing_codes=[]`。
- [ ] `stateConsistency.consistent=true` 且无 violation。
- [ ] 保存与未发布证据文件存在且 hash 一致。
- [ ] mutation ledger 无 `UNKNOWN` 或未对账动作。
- [ ] 交付范围没有被扩大到发布、旧批量任务或无人值守。

## 自检命令

没有真实现场证据时：

```bat
scripts\final-delivery-check.bat -RequireCleanWorktree -CheckPortableDesktop -ExpectedRealDxmWriteReadiness BLOCKED -ExpectedRealDxmSingleSaveEndToEnd pending_live_dxm_validation
```

完成同 HEAD 商品箱 L2 和真实单次保存后：

```bat
scripts\final-delivery-check.bat -RequireCleanWorktree -CheckPortableDesktop -ExpectedRealDxmWriteReadiness READY -ExpectedRealDxmSingleSaveEndToEnd passed
```

正式验收不要使用 `-SkipBrowserQA`。

## 报告判读

不要只看 `ok`。至少联合读取：

- `okScope`
- `realDxmMutationAllowed`
- `realDxmMutationScope`
- `realDxmWriteReadiness`
- `realDxmSingleSaveEndToEnd`
- `singleSaveAcceptance`
- `singleSaveAcceptanceReadiness`
- `stateConsistency`
- `sourcePackageReadiness`
- Git/build/package identity 和证据路径

`READY` 的含义受 `realDxmMutationScope` 限制；它不自动包含受控整批，更不包含发布或无人值守。

## 常见失败

- L2 `not_run/mock_passed/failed`：重新取得用户批准后运行真实商品箱只读检查。
- `missing_product_box_snapshot`：从当前商品箱重新选择商品并创建任务。
- `approval_required`：重新申请服务端批准，不要注入或复用 token。
- `missing_save_stage`：检查 runner、页面和保存回包；不要手工补报告。
- `missing_unpublished_proof`：重新执行独立未发布读回，不要复用保存截图。
- `invalid_l3_evidence`：证据文件缺失、越界、类型或 hash 不一致，重新执行本次保存。
- `inconsistent_state`：保留失败历史，创建新任务；不要修改旧终态伪装成功。
- ledger `UNKNOWN`：停止自动化并人工对账。

## 当前边界

源码或包发生任何变化后，旧测试、旧 L2、旧现场保存和旧 EXE 都自动降级为历史证据。正式交付必须从最终合并 HEAD 重新构建、重新 smoke、重新运行门禁并记录新 hash。
