# DXM Agent Console 生产级版本计划

更新日期：2026-06-24

## 1. 最终产品定义

DXM Agent Console 是面向普通店小秘运营用户的真实浏览器自动化控制台，不是测试工作台、诊断工具或本地演示系统。

最终交付的主路径只有两段：

1. **数据采集认领**：在真实店小秘浏览器中进入数据采集页，把真实商品认领到采集箱。
2. **采集箱编辑保存**：从采集箱打开已认领商品的编辑页，按模板填写字段，只点击保存，不发布。

本阶段明确不做：

- 发布
- 保存并发布
- 移入待发布
- 批量保存
- 无人值守发布
- 使用本地测试商品冒充真实商品流程

## 3. 版本路线

### V0.9 生产壳收口版

目标：让软件不再像测试台，用户打开后能理解系统只做什么。

交付内容：

- 侧边栏使用业务词：店小秘登录、数据采集认领、采集箱编辑保存、模板中心、执行浏览器、结果与问题。
- 首页只回答三件事：现在做什么、为什么不能继续、下一步点哪里。
- 技术概念下沉：L2、L3、probe、run-id、HAR、路径、原始异常默认不展示给普通用户。
- 测试商品、QA 商品、本地演示商品不出现在主路径。
- 发布、批量、无人值守仍无入口。

完成标准：

- 打开 EXE 后用户能看懂“先认领，再编辑保存”。
- 用户不需要理解技术门禁也能知道下一步。
- 所有主路径文案不出现测试工程词。

### V1.0 单店单品真实可用版

目标：单个店铺、单个真实商品可以完成完整只保存流程。

交付内容：

- 用户填写或自动带出店小秘账号密码。
- 打开显式真实浏览器完成登录。
- 创建数据采集认领任务。
- 从数据采集页认领 1 个真实商品到采集箱。
- 采集箱编辑保存页只能选择已认领商品。
- 保存前要求人工确认。
- Agent 只点击保存。
- 结果页显示保存成功和未发布证明。

完成标准：

- 不依赖开发者命令行。
- 不依赖本地测试商品。
- 完成一次真实 DXM 两段式验收：
  - 数据采集认领成功
  - 采集箱确认成功
  - 编辑页填写成功
  - 保存成功
  - 未发布证明成功

### V1.1 数据采集认领生产版

目标：第一段成为稳定、可解释、可恢复的独立功能。

交付内容：

- 认领任务表单：
  - 店铺
  - 平台
  - 商品线索或关键词
  - 类目
  - 认领标记
- 浏览器动作：
  - 打开数据采集
  - 搜索或定位商品
  - 唯一匹配确认
  - 认领到采集箱
  - 打开采集箱确认
- 认领记录：
  - 店铺
  - 平台
  - 商品标题
  - 来源链接
  - 采集箱标题
  - 认领时间
  - 截图或 DOM 证据
  - 失败原因

完成标准：

- 认领成功后第二段能直接选择该商品。
- 没找到商品、多个匹配、未登录、验证码、权限不足、页面变更都有中文处理建议。
- 认领阶段不保存、不发布、不批量写入。

### V1.2 采集箱编辑保存生产版

目标：第二段只从已认领商品开始，并完成可靠只保存。

交付内容：

- 只能选择状态为“已认领到采集箱”的商品。
- 保存前展示：
  - 商品标题
  - 店铺
  - 类目
  - 当前模板
  - 本次将填写的分区
  - 只保存、不发布确认
- 编辑页填写分区：
  - 店铺与任务基础
  - 类目与标题
  - SKU / 价格 / 库存
  - 图片与素材
  - 包装物流
  - 合规 / 海关
  - 半托管
  - 店小秘引用模板
  - 执行策略
- 保存证明：
  - 保存接口或页面成功提示
  - 保存后未发布证明
  - 发布类入口未触发证明

完成标准：

- 无已认领商品时不能启动保存。
- 未人工确认时不能启动保存。
- 出现发布、保存并发布、移入待发布风险时停止。
- 保存失败后用户知道下一步怎么恢复。

### V1.3 模板中心生产版

目标：配置从“写死测试值”升级为客户可维护的多模板系统。

交付内容：

- 模板类型：
  - 系统默认模板
  - 店铺默认模板
  - 类目默认模板
  - 手动选择模板
  - 本次任务覆盖
- 模板操作：
  - 新建
  - 复制
  - 重命名
  - 删除或停用
  - 保存为店铺模板
  - 保存为类目模板
  - 仅本次任务使用
  - 套用默认测试模板
- 表单体验：
  - 每次只展开一个分区
  - 字段中文化
  - 保存状态明确
  - 未保存修改明确
  - 必填缺失明确
  - 执行取值来源明确
- 执行取值优先级：
  - 本次任务覆盖
  - 手动选择模板
  - 类目默认模板
  - 店铺默认模板
  - 系统默认模板

完成标准：

- 用户能明确知道当前用哪套模板。
- 用户能明确知道刚填的内容是否已保存。
- 用户能在执行前看到最终会填写哪些值。
- 普通用户路径不暴露英文 key。

### V1.4 真实浏览器 Agent 稳定版

目标：浏览器执行过程可见、常开、可接管、可恢复。

交付内容：

- 真实浏览器显式打开，不隐藏。
- 浏览器内常驻黑色中文 HUD。
- HUD 显示：
  - 当前阶段
  - 当前步骤
  - 正在做什么
  - 是否需要人工
  - 失败原因
- HUD 在页面跳转、刷新、新标签页后自动重注入。
- Agent 不因单步失败直接关闭浏览器。
- 浏览器关闭、Agent 崩溃、登录失效、验证码等待都能回传到主窗口。
- 主窗口、浏览器 HUD、结果页三处状态一致。

完成标准：

- 浏览器不能运行到一半闪退且没有结果。
- HUD 不能运行到一半消失。
- 失败后浏览器现场尽量保留。
- 用户能选择人工接管、重试、重新打开浏览器。

### V1.5 日志与结果问题生产版

目标：让客户看懂发生了什么，而不是阅读工程日志。

交付内容：

- 默认日志只显示业务事件：
  - 已打开真实浏览器
  - 已检测店小秘登录
  - 已进入数据采集
  - 已找到商品
  - 已认领到采集箱
  - 已打开编辑页
  - 正在填写标题
  - 正在处理图片
  - 正在只保存
  - 保存成功
  - 已确认未发布
- 原始日志放入维护诊断折叠区。
- 失败卡片统一结构：
  - 发生了什么
  - 为什么停止
  - 下一步怎么做
  - 维护人员详情

完成标准：

- 普通用户不看到 `Internal Server Error`、`greenlet`、`HAR`、`run-id` 作为主错误。
- 日志不重叠、不遮挡、不刷屏。
- 每个失败都有一个明确恢复动作。

### V1.6 免安装交付版

目标：输出可发给客户的免安装 Windows 包。

交付内容：

- 一个 EXE 启动控制台。
- 不要求用户打开两个服务窗口。
- 后端、前端、浏览器 Agent 由桌面程序托管。
- 交付目录包含：
  - `DXM-Agent-Console.exe` 或 portable exe
  - `resources`
  - 快速使用说明
  - 故障处理说明
  - 验收报告
  - 版本说明
- 启动自检：
  - 端口占用
  - resources 是否完整
  - 浏览器依赖是否存在
  - 数据目录是否可写
  - 后端是否启动成功

完成标准：

- 用户双击 EXE 可进入主控制台。
- 账号密码可本机加密保存。
- 当前分支重新打包，不沿用旧包。
- 完成真实两段式验收后再输出最终路径。

## 4. 推荐菜单结构

最终侧边栏建议保留 7 个主入口：

| 菜单 | 用户理解 | 包含能力 |
| --- | --- | --- |
| 首页 | 今天该做什么 | 当前步骤、阻断原因、下一步按钮、最近结果 |
| 店小秘登录 | 先把店小秘连上 | 账号密码、本机记住、打开登录页、检测登录状态 |
| 数据采集认领 | 第一段，把商品放进采集箱 | 店铺平台、商品线索、认领标记、启动认领、认领结果 |
| 采集箱编辑保存 | 第二段，只保存商品 | 选择已认领商品、确认模板、人工确认、启动保存 |
| 模板中心 | 管理填写规则 | 模板列表、分区表单、默认模板、执行取值预览 |
| 执行浏览器 | 看 Agent 操作现场 | 浏览器状态、HUD、Agent 生命周期、人工接管 |
| 结果与问题 | 看结果和处理失败 | 保存报告、未发布证明、失败恢复、维护诊断 |

不再作为普通用户一级菜单：

- 证据中心：合并到结果与问题。
- 异常池：合并到结果与问题。
- Agent 控制台：改名为执行浏览器。
- 配置中心：改名为模板中心。
- 任务中心：拆入数据采集认领和采集箱编辑保存。

## 5. 主窗口规则

每个页面只保留一个主动作。

页面统一结构：

1. 标题：用户当前在做什么。
2. 状态摘要：现在能不能继续。
3. 主按钮：下一步点哪里。
4. 当前步骤必要表单。
5. 折叠详情：技术状态、原始日志、证据路径。

默认禁止展示：

- 大段技术说明
- 原始日志刷屏
- 证据路径
- run-id
- L2 / L3
- API 错误原文
- 大量同时展开的配置分区

## 6. 交付验收场景

### 场景 A：首次使用

1. 用户打开 EXE。
2. 首页提示先登录店小秘。
3. 用户填写账号密码并勾选记住。
4. 打开真实浏览器完成登录或验证码。
5. 主窗口显示店小秘已登录。

通过标准：用户不用看日志也知道登录是否完成。

### 场景 B：数据采集认领

1. 用户进入数据采集认领。
2. 选择店铺和平台。
3. 输入商品线索或关键词。
4. 点击开始认领。
5. 真实浏览器进入数据采集页。
6. HUD 显示正在搜索、正在认领、正在确认采集箱。
7. 认领成功后生成可编辑商品。

通过标准：采集箱编辑保存页能选择该商品。

### 场景 C：采集箱编辑保存

1. 用户进入采集箱编辑保存。
2. 选择已认领商品。
3. 确认模板。
4. 人工确认只保存。
5. Agent 打开真实编辑页并填写。
6. Agent 只点击保存。
7. 结果页显示保存成功和未发布证明。

通过标准：保存成功证据和未发布证明同时存在。

### 场景 D：失败恢复

1. 页面变化、验证码、权限、商品找不到或浏览器关闭。
2. 主窗口显示中文失败卡片。
3. 用户看到下一步动作。
4. 用户可人工接管浏览器。
5. 修正后可继续或重新创建任务。

通过标准：不出现只有技术错误、无法判断下一步的死局。

## 7. 开发执行顺序

### P0：先保证真实流程能跑

1. 修复浏览器 Agent 常开和异常不闪退。
2. 修复 HUD 常驻和页面跳转后重注入。
3. 修复登录状态同步，避免浏览器已登录但控制台提示未登录。
4. 强制保存任务只能使用已认领采集箱商品。
5. 跑通真实数据采集认领到采集箱。
6. 跑通真实采集箱编辑保存。

### P1：再保证普通用户能用

1. 页面继续瘦身，每页一个主动作。
2. 模板中心补齐多模板管理。
3. 保存状态和执行取值预览做成固定首屏信息。
4. 日志改为业务事件。
5. 结果与问题页统一失败恢复结构。

### P2：最后做交付包和文档

1. 当前分支重新构建前端。
2. 当前分支重新构建免安装 EXE。
3. 运行桌面包验证脚本。
4. 保存真实验收报告。
5. 更新快速使用说明和故障处理说明。
6. 推送代码和交付路径。

## 8. 什么时候算完成

只有同时满足以下 12 项，项目才算达到可交付：

1. 主流程是两段式：数据采集认领 -> 采集箱编辑保存。
2. 主流程不依赖本地测试商品。
3. 真实浏览器显式打开并常开。
4. 浏览器 HUD 常驻，跳转后不丢失。
5. 店小秘登录状态在浏览器和控制台一致。
6. 数据采集认领真实成功，并记录可追踪证据。
7. 采集箱编辑保存真实成功，并记录保存证据。
8. 未发布证明真实存在。
9. 模板中心支持多套模板、中文分区、保存反馈、执行取值预览。
10. 普通用户路径没有工程术语干扰。
11. 发布、批量、无人值守被 UI 和 API 双层阻断。
12. 当前分支重新打出免安装 EXE，并完成真实端到端验收报告。

## 9. 下一步执行项

下一步优先推进 **V1.4 真实浏览器 Agent 稳定版**，因为它是当前最大交付风险。

具体任务：

1. 排查执行浏览器和控制台浏览器是否为同一会话。
2. 增加任务运行中的主窗口轮询，避免任务状态停留在旧状态。
3. 增加 Agent 异常退出保护，失败时保留浏览器现场。
4. 增加中文 HUD 状态映射。
5. 在页面跳转后重注入 HUD。
6. 将原始技术错误默认收进维护诊断。
7. 用真实浏览器验证 HUD 常驻和状态一致。
