# DXM Agent Console 生产级版本计划

更新日期：2026-06-24

当前分支：`feature/dxm-production-two-stage`

## 1. 产品定位

DXM Agent Console 是面向普通店小秘运营用户的真实浏览器自动化控制台。

它不是测试工具、诊断台、本地演示系统，也不是“打开截图给用户看”的辅助工具。用户最终要拿到的是一个免安装桌面程序，能显式打开真实店小秘浏览器，并按用户确认的配置执行真实业务动作。

当前生产级主路径只允许两段：

1. **数据采集认领到采集箱**
   - 在真实店小秘浏览器中进入数据采集。
   - 定位真实商品。
   - 将商品认领到采集箱。
   - 记录来源链接、标题、店铺、平台、认领结果。

2. **采集箱编辑商品并只保存**
   - 只从已经认领到采集箱的商品开始。
   - 打开真实编辑页。
   - 按模板填写商品信息。
   - 人工确认后只点击“保存”。
   - 证明保存成功且未发布。

当前明确不开放：

- 发布
- 保存并发布
- 移入待发布
- 批量保存
- 无人值守写入
- 用测试商品冒充真实生产流程
- 未经采集箱确认直接进入保存

## 2. 当前阶段判断

按生产可交付口径，当前整体约为 **70%**。这个百分比不是最终验收结论，只表示代码和界面已经从测试工作台转向两段式产品，但完整真实链路还需要重新验收。

| 模块 | 当前判断 | 主要缺口 |
| --- | --- | --- |
| 产品方向 | 已明确 | 需要所有页面和文档完全统一为两段式 |
| 菜单与信息架构 | 已开始重构 | 需要继续拆细业务入口，隐藏技术入口 |
| 店小秘登录 | 基础可用 | 登录状态同步、可恢复提示还要稳定 |
| 数据采集认领 | 已有入口 | 真实认领到采集箱需要端到端验收 |
| 采集箱编辑保存 | 有历史保存证据 | 必须强绑定已认领商品并重新验收 |
| 模板中心 | 已有中文分区和多模板雏形 | 需要保存反馈、取值预览、模板管理闭环 |
| 真实浏览器 Agent | 风险最高 | 需要常开、HUD 常驻、失败不闪退 |
| 日志和问题处理 | 已开始用户化 | 需要彻底从工程日志改为业务事件 |
| 免安装 EXE | 有打包基础 | 需要基于当前分支重新打包并验收 |

## 3. 目标版本定义

### V0.9：生产壳和菜单收口版

目标：用户打开软件后，能清楚理解系统只做“两段式只保存”。

交付范围：

- 侧边栏改为业务菜单，不使用“Agent 控制台”“L2”“probe”等技术概念作为主入口。
- 首页只展示：
  - 当前该做什么
  - 为什么不能继续
  - 下一步点哪里
- 顶部状态条只保留一个主结论和一个主按钮。
- 技术日志、证据路径、run-id、HAR、原始异常全部下沉到维护诊断。
- 测试商品、QA 商品、本地演示商品不出现在普通用户主路径。

验收标准：

- 新用户能在 1 分钟内看懂：先认领，再编辑保存。
- 用户不需要理解技术门禁也能知道下一步。
- 任何发布、批量、无人值守入口不可见。

### V1.0：单店单品真实两段式可用版

目标：单个店铺、单个真实商品完成完整生产主路径。

交付范围：

- 店小秘账号可本机加密保存。
- 用户显式打开真实店小秘浏览器并完成登录。
- 第一段：从数据采集认领 1 个真实商品到采集箱。
- 第二段：从采集箱选择已认领商品，套用模板，人工确认，只保存。
- 结果页展示保存成功和未发布证明。

验收标准：

- 不依赖开发命令行。
- 不依赖测试商品。
- 真实浏览器完成一次完整流程：
  1. 登录成功
  2. 数据采集页定位商品
  3. 认领到采集箱
  4. 采集箱确认同一商品
  5. 编辑页填写字段
  6. 只点击保存
  7. 保存成功
  8. 未发布证明存在

### V1.1：模板中心生产版

目标：把“配置中心”升级为客户可维护的模板系统。

交付范围：

- 支持多套模板：
  - 系统默认模板
  - 店铺默认模板
  - 类目默认模板
  - 手动选择模板
  - 本次任务覆盖
- 表单按店小秘编辑页分区：
  - 店铺与任务基础
  - 类目与标题
  - SKU / 价格 / 库存
  - 图片与素材
  - 包装物流
  - 合规 / 海关
  - 半托管
  - 店小秘引用模板
  - 执行策略
- 每个分区固定三个主动作：
  - 仅本次任务使用
  - 保存为模板
  - 套用默认模板
- 页面固定展示：
  - 当前使用哪套模板
  - 是否已保存
  - 执行最终会用哪个值
  - 值来自哪里

验收标准：

- 普通用户看不到英文字段 key。
- 用户能保存多套模板并选择使用。
- 用户修改字段后能明确知道是否已保存。
- 启动保存前能预览最终填写值。

### V1.2：真实浏览器 Agent 稳定版

目标：用户能看见 Agent 在真实浏览器中做什么，并能接管。

交付范围：

- 真实浏览器显式打开，不隐藏。
- 浏览器内常驻中文 HUD。
- HUD 显示业务步骤，例如：
  - 开始任务
  - 打开数据采集
  - 定位商品
  - 认领到采集箱
  - 打开编辑页
  - 填写标题
  - 选择分类
  - 处理图片
  - 选择物流模板
  - 只保存
  - 检查未发布
- HUD 在刷新、跳转、新页面后自动重注入。
- Agent 失败时保留浏览器现场，不静默关闭。
- 主窗口、浏览器 HUD、结果页状态一致。

验收标准：

- 浏览器运行中不闪退。
- HUD 不会运行到一半消失。
- 失败后用户能看到当前卡在哪一步。
- 用户可人工接管浏览器，再返回控制台继续或重试。

### V1.3：错误恢复和日志用户化版

目标：普通运营用户看得懂失败原因和恢复动作。

交付范围：

- 默认日志只显示业务事件。
- 原始技术日志放到“维护人员查看技术状态”。
- 所有失败卡片统一为：
  - 发生了什么
  - 为什么停止
  - 下一步怎么做
  - 维护人员详情
- 常见失败要有明确恢复动作：
  - 未登录
  - 验证码未处理
  - 商品未找到
  - 多个商品匹配
  - 未认领到采集箱
  - 模板缺失
  - 浏览器关闭
  - 保存失败
  - 页面出现发布风险

验收标准：

- 普通用户主路径不出现 `Internal Server Error`、`greenlet`、`Playwright`、`HAR`、`run-id`。
- 每个失败都有一个可点击或可执行的下一步。
- 日志不刷屏、不遮挡主内容、不重叠。

### V1.4：免安装客户交付版

目标：输出客户可以直接使用的 Windows 免安装版本。

交付范围：

- 一个 EXE 启动主控制台。
- 不再要求用户面对两个服务窗口。
- 后端、前端、浏览器 Agent 由桌面程序托管。
- 交付目录包含：
  - 免安装 EXE
  - resources 资源目录
  - 快速使用说明
  - 故障处理说明
  - 真实验收报告
  - 版本说明
- 启动自检：
  - 端口占用
  - resources 是否完整
  - 浏览器依赖是否存在
  - 数据目录是否可写
  - 后端是否启动成功

验收标准：

- 用户双击 EXE 可以进入控制台。
- 账号密码能本机加密保存。
- 当前分支重新打包，不沿用旧包。
- 桌面包验证脚本通过。
- 完成真实两段式端到端验收。

### V2.0：扩展能力版

目标：在 V1.x 稳定后再考虑扩展。

候选能力：

- 小批量只保存
- 多店铺模板继承
- 团队权限
- 任务队列
- 异常自动重试
- 半无人值守

硬边界：

- V2.0 之前不开放无人值守写入。
- V2.0 之前不开放批量生产写入。

## 4. 推荐菜单结构

最终侧边栏建议按“用户任务”拆，而不是按技术模块拆。

| 分组 | 菜单 | 用户理解 | 子功能 |
| --- | --- | --- | --- |
| 准备 | 首页 | 今天该做什么 | 当前步骤、阻断原因、下一步按钮、最近结果 |
| 准备 | 店小秘登录 | 先把店小秘连上 | 账号密码、记住账号、打开登录页、检测登录状态 |
| 第一段 | 数据采集认领 | 把商品放进采集箱 | 店铺平台、商品线索、搜索定位、认领、采集箱确认 |
| 第一段 | 采集箱商品 | 管理已经认领的商品 | 已认领商品列表、来源链接、采集箱标题、状态校验 |
| 第二段 | 编辑页模板 | 维护填写规则 | 多模板、中文分区表单、默认模板、取值预览 |
| 第二段 | 只保存执行 | 启动真实保存 | 选择已认领商品、人工确认、启动保存、保存边界 |
| 现场 | 浏览器现场 | 看 Agent 真实操作 | 真实浏览器状态、HUD、人工接管、重试 |
| 复盘 | 结果与问题 | 看结果和处理失败 | 保存报告、未发布证明、失败恢复、维护诊断 |
| 系统 | 系统设置 | 管理本机运行环境 | 数据目录、日志路径、资源自检、版本信息 |

不建议作为一级菜单：

- Agent 控制台
- 证据中心
- 异常池
- L2 / L3
- 只读 Probe
- 任务中心
- 配置中心

这些概念仍然可以存在，但只能放在维护诊断或高级折叠区。

## 5. 模块功能拆分

### 5.1 店小秘登录

主功能：

- 输入账号密码。
- 勾选本机记住。
- 打开真实店小秘浏览器。
- 检测登录状态。
- 验证码或二次验证时等待人工处理。

必须修复：

- 浏览器已经登录但控制台仍提示未登录。
- 登录失败只显示技术错误。
- 重新打开登录页导致多浏览器会话混乱。

### 5.2 数据采集认领

主功能：

- 选择店铺和平台。
- 输入商品线索、关键词或来源链接。
- 打开数据采集页。
- 搜索或定位目标商品。
- 唯一匹配确认。
- 认领到采集箱。
- 打开采集箱确认。

记录字段：

- 店铺
- 平台
- 商品标题
- 来源链接
- 采集箱标题
- 认领标记
- 认领时间
- 认领证据

阻断规则：

- 未登录不能认领。
- 找不到商品不能认领。
- 多个匹配必须人工确认。
- 认领失败不能进入保存。

### 5.3 采集箱商品

主功能：

- 展示已认领商品列表。
- 显示来源链接和采集箱匹配关系。
- 标记哪些商品可以进入编辑保存。
- 发现标题变更时用来源链接辅助匹配。

阻断规则：

- 不是采集箱确认商品，不能进入保存。
- 测试商品不能进入生产保存。
- 已失败或旧任务不能直接复用保存证据。

### 5.4 编辑页模板

主功能：

- 多套模板管理。
- 分区表单填写。
- 保存为店铺模板。
- 保存为类目模板。
- 另存为新模板。
- 仅本次任务使用。
- 套用默认模板。
- 执行取值预览。

取值优先级：

1. 本次任务覆盖
2. 手动选择模板
3. 类目默认模板
4. 店铺默认模板
5. 系统默认模板
6. 商品原始数据

### 5.5 只保存执行

主功能：

- 选择已认领商品。
- 展示本次模板和关键字段。
- 人工确认“只保存、不发布”。
- 启动 Agent 打开编辑页。
- 填写字段。
- 只点击保存。
- 验证未发布。

阻断规则：

- 未通过采集箱确认不能启动。
- 模板缺失不能启动。
- 未人工确认不能启动。
- 出现发布、保存并发布、移入待发布风险立即停止。

### 5.6 浏览器现场

主功能：

- 显示真实浏览器是否打开。
- 显示 Agent 是否运行。
- 显示 HUD 是否在线。
- 支持人工接管。
- 支持保留现场。
- 支持失败后重试。

核心要求：

- 浏览器必须显式，不做隐藏后台操作。
- HUD 必须常驻，不随页面跳转消失。
- Agent 失败不应让浏览器直接闪退。

### 5.7 结果与问题

主功能：

- 保存成功报告。
- 未发布证明。
- 认领失败报告。
- 保存失败报告。
- 恢复建议。
- 维护诊断。

结果报告必须包含：

- 商品标题
- 店铺
- 平台
- 来源链接
- 采集箱确认
- 模板名称
- 保存结果
- 未发布状态
- 时间
- 证据路径或证据摘要

## 7. 交付完成判定

只有同时满足以下条件，才算项目达到客户可交付状态：

1. 双击免安装 EXE 可启动主控制台。
2. 用户不需要启动两个命令行窗口。
3. 店小秘真实浏览器显式打开并保持在线。
4. 浏览器 HUD 常驻，显示中文业务步骤。
5. 第一段真实完成：数据采集认领到采集箱。
6. 第二段真实完成：采集箱编辑商品并只保存。
7. 保存成功证据存在。
8. 未发布证明存在。
9. 模板中心支持多套模板和中文分区表单。
10. 启动保存前能看到最终执行取值。
11. 失败时用户能看懂下一步怎么处理。
12. 普通用户主路径不暴露工程术语。
13. 发布、批量、无人值守在 UI 和 API 双层阻断。
14. 当前分支自动测试通过。
15. 当前分支桌面包验证通过。
16. 真实验收报告、EXE hash、Git HEAD 三者一致。

## 8. 下一轮开发建议

下一轮不要先做更多视觉微调，先做 **P0 真实流程可信**。

具体顺序：

1. 检查登录状态同步：浏览器已登录时控制台必须同步为已登录。
2. 检查执行浏览器生命周期：运行失败后浏览器不能闪退。
3. 检查 HUD 注入：跳转、刷新、新页面都要保持。
4. 检查数据采集认领：必须真实认领到采集箱。
5. 检查采集箱商品身份：第二段只能选择第一段认领成功的商品。
6. 检查只保存执行：只保存，不触发任何发布相关按钮或请求。
7. 完成一次真实验收后，再重新打免安装 EXE。
