# 1. 项目背景

当前大量跨境卖家使用店小秘完成商品刊登、保存待发布、发布、模板复用、订单与物流处理。

但在“刊登”这个链路里，仍存在明显痛点：

1. 商品采集后仍需大量人工操作
2. 标题、类目、资质、图片、SKU、价格、运费、详情、合规信息需要逐项填写
3. 半托管场景下还需补充报价、重量、尺寸、履约参数、责任主体等字段
4. 现有自动化工具大多是黑盒脚本，卖家缺乏信任，不敢长期使用
5. 卖家不愿迁移 ERP，也不愿交出账号给云端托管工具

因此需要一款：

“本地运行、全流程可见、可人工接管、围绕店小秘进行自动刊登”的客户端工具。

# 2. 产品定位

## 2.1 产品名称
店小秘自动刊登助手

## 2.2 产品定义
一款本地客户端形态的自动化刊登工具，用户继续使用店小秘，软件通过模板中心、任务中心和可视化 RPA 执行区，自动操控店小秘完成商品创建、保存待发布、自动发布或半托管报价提交。

## 2.3 核心价值
1. 不改变卖家现有 ERP 使用习惯
2. 不要求卖家迁移到新系统
3. 账号密码在真实店小秘页面输入，提升信任度
4. 自动化流程对用户可见，随时可人工接管
5. 把重复的人工填表动作变成可复用模板 + 自动执行流程

# 3. 目标用户

## 3.1 核心用户
1. 使用店小秘做速卖通铺货的跨境卖家
2. 需要批量上架、多店铺、多 SKU 的运营团队
3. 做跨境 POP、半托管或兼顾多场景的卖家
4. 不愿自建中台，但想提升刊登效率的中小卖家

## 3.2 次级用户

# 4. 用户痛点

## 4.1 现状痛点
1. 采集不是问题，清洗和填表才是问题
2. 页面操作繁琐，重复劳动多
3. 一旦涉及：
   - 白底图
   - 营销图
   - 视频
   - 资质
   - 欧盟负责人
   - 制造商
   - 运费模板
   - 半托管报价
   人工成本会快速上升
4. 现有脚本工具不可视、不可控、不可信
5. 错误原因不透明，异常处理成本高

## 4.2 产品机会点
1. 通过模板中心沉淀配置
2. 通过任务中心批量执行
3. 通过 RPA 实时执行区建立信任
4. 通过异常池降低人工返工成本

# 5. 产品目标

## 5.1 业务目标
1. 让卖家在不更换 ERP 的前提下使用自动刊登工具

3. 实现“模板中心 + 自动执行 + 异常池兜底”的商用闭环

## 5.3 MVP 成功标准
1. 支持店小秘速卖通刊登场景
2. 支持商品导入 → 模板绑定 → 自动执行 → 结果回写
3. 支持保存待发布与自动发布
4. 支持异常池与截图日志
5. 支持核心模板中心

# 8. 核心业务流程

## 8.1 标准流程
```text
连接店小秘
→ 导入商品
→ 预处理商品
→ 绑定模板
→ 校验字段
→ 入执行队列
→ 执行器操控店小秘
→ 保存待发布 / 自动发布 / 半托管提交报价
→ 回写结果
→ 异常池处理
```

## 8.2 半托管流程
```text
连接店小秘
→ 导入商品
→ 绑定半托管模板
→ 填写标题/类目/资质
→ 上传主图/白底图/营销图/视频
→ 填写 SKU/尺码/价格/报价
→ 填写重量/尺寸/履约参数
→ 填写欧盟负责人/制造商/合规信息
→ 提交半托管链路
→ 记录结果与异常
```

# 14. 核心规则需求

## 14.1 登录规则
1. 只能通过真实店小秘页面登录
2. 不支持软件自定义账号密码输入框
3. 登录态本地保存

## 14.2 安全规则
1. 商品与执行证据默认本地保存
2. 敏感数据不上传云端
3. 云端仅用于订阅、配置、AI 服务

## 14.3 执行规则
1. 每个 Job 都必须有状态
2. 每个关键步骤都必须有证据
3. 每个失败都必须进入异常池
4. 每个异常都必须可重试

## 14.4 可视化规则
1. 当前动作必须高亮
2. 步骤树必须可见
3. 人工接管必须一键触达
4. 日志必须实时刷新

# 15. 非功能需求

## 15.1 性能

2. 批量任务支持断点续跑

1. 本地敏感数据加密保存
2. 登录态与截图文件隔离存储

## 15.3 稳定性
1. 页面元素变化支持热修复配置

3. 异常状态不能让任务整体崩溃

## 15.4 可维护性
1. 选择器与页面配置可热更新
2. 模板中心可扩展
3. 平台适配层可扩展到其他平台

# 19. 最终结论

这款产品不是简单的“店小秘脚本工具”，而是：

一个围绕店小秘构建的、可视化、可接管、模板驱动的自动刊登客户端。

其成功关键不在于“点得快”，而在于：
1. 字段建模完整
2. 模板中心足够强
3. 执行过程足够透明
4. 异常池足够可用
5. POP 与半托管链路都能覆盖

一句话总结：

这份 PRD 的目标，是把产品从“自动点页面”升级为“可商业化的自动刊登系统”。
