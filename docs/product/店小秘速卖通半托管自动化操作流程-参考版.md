# 店小秘速卖通半托管自动化操作流程（参考版）

> 版本：v0.1
> 依据：2026-05-20 真实浏览器跑通流程与现有 PRD / 字段矩阵
> 适用范围：店小秘速卖通采集箱商品编辑、保存待发布、半托管服务参与与半托管信息填写
> 文档定位：给产品、自动化执行器、配置中心、测试验收共同使用的流程参考
> 当前状态提示：本文是流程参考和目标设计，不代表 2026-05-25 的交付放行状态。当前真实 L2 双目标未通过，真实 `claim_only` / `single_save` / `batch_save` 必须保持阻断。

---

# 1. 核心结论

这条链路不应设计成“AI 临场判断并操作页面”，而应设计成：

```text
运行前配置完整
→ 执行器按配置和页面状态自动执行
→ 每一步读取 DOM / 页面接口 / 提示信息校验
→ 失败进入异常池
→ 成功只保存到待发布
```

自动化运行中不应临时决定关键业务字段。所有字段策略都应在任务启动前通过系统配置、模板、规则或商品数据确定。

当前推荐的执行边界：

- 可以自动：认领、备注、编辑字段、选择模板、选择图片、填写半托管信息、保存。
- 默认禁止：立即发布、继续发布、绕过平台校验、伪造无依据资质或条码。
- 可以留空：页面允许且配置允许留空的可选字段，例如货品条码。
- 必须中断：缺少必填配置、页面校验失败、商品不属于当前任务、出现发布确认、登录失效、验证码、页面结构严重变化。

# 2. 术语定义

| 术语 | 含义 |
|---|---|
| 采集箱 | 店小秘速卖通采集箱，真实路径通常为 `/web/smt/smtProductList/draft` |
| 普通编辑页 | 店小秘速卖通商品编辑页，填写标题、类目、属性、图片、SKU、模板、合规等信息 |
| 半托管参与 | 在普通编辑页“其他信息”中勾选半托管服务参与 |
| 半托管编辑页 | 点击“编辑半托管信息”后进入的页面，真实页面标题为“编辑速卖通半托管” |
| 领取标记 | 用于确认商品归属当前自动化任务的备注，例如 `AI认领` |
| 保存 | 保存商品到待发布或保存半托管信息，不触发平台上架 |
| 发布 | `立即发布`、`发布`、`继续发布`、`保存并发布` 等会使商品进入线上发布链路的动作 |
| 配置中心 | 系统内预先配置店铺、类目、字段、模板、图片、SKU、价格、库存、物流、半托管策略的模块 |
| 异常池 | 自动化失败后保存错误、截图、DOM 快照、接口返回、建议动作的处理队列 |

# 3. 安全原则

## 3.1 商品归属原则

执行器只能操作明确属于当前任务的商品。

必须满足至少一个归属条件：

1. 商品来自当前任务队列，并且任务中有店铺、平台、商品 ID 或标题匹配。
2. 商品行已被当前任务写入领取标记，例如 `AI认领`。
3. 商品详情页中的店铺、标题、SKU 前缀或商品 ID 与任务 payload 一致。

不满足归属条件时，执行器必须停止，不能继续编辑。

## 3.2 发布隔离原则

默认模式下，执行器只能点击：

- `保存`
- `提交`（仅限备注、弹窗确认、图片选择、模板选择等非发布动作）
- `编辑半托管信息`
- `保存并返回编辑速卖通信息`（如业务确认该按钮仅保存，不发布）

执行器禁止点击：

- `立即发布`
- `发布`
- `继续发布`
- `保存并移入待发布`（如当前产品策略明确禁止移动状态）
- 任何含义不明且可能触发发布的按钮

如果页面弹出发布确认或风险确认，执行器必须停止并记录异常。

## 3.3 字段真实性原则

字段来源必须可追溯。

允许自动生成：

- 标题
- SKU
- 货品编码
- 商品编码
- 普通描述
- 详情页文案
- 库存
- 价格
- 货值

不允许无依据伪造：

- 品牌授权
- IP 授权
- 专利供应
- 欧盟责任人
- 制造商真实信息
- MSDS / CE / 电池证书
- UPC / EAN / GTIN 条码

对于可选字段，系统可以配置：

```text
留空 / 使用 SKU / 使用系统规则生成 / 从外部表导入
```

默认建议：货品条码留空，除非用户导入真实条码或明确配置使用内部编码。

# 4. 自动化总流程

```text
准备任务配置
→ 检查登录态
→ 进入速卖通采集箱
→ 定位目标商品
→ 领取或确认领取标记
→ 进入普通商品编辑页
→ 填写普通商品信息
→ 勾选半托管服务参与
→ 普通页保存或校验
→ 点击编辑半托管信息
→ 填写半托管信息
→ 点击保存
→ 校验保存成功
→ 写入执行报告
```

# 5. 运行前配置

自动化运行前必须准备完整配置。运行过程中不应再临时询问用户，也不应让 AI 临场判断。

## 5.1 店铺与账号配置

| 配置项 | 示例 | 是否必需 |
|---|---|---|
| 平台 | 速卖通 | 必需 |
| 店铺 | Dang Kang | 必需 |
| 店铺 ID / 店铺名称匹配规则 | 精确匹配店铺名 | 必需 |
| 登录态策略 | 使用本地真实浏览器登录态 | 必需 |
| 会话失效处理 | 停止并进入异常池 | 必需 |
| 执行账号 | 当前客户端登录账号 | 必需 |

## 5.2 任务配置

| 配置项 | 示例 | 说明 |
|---|---|---|
| 任务名称 | 立牌类谷子半托管保存任务 | 用于日志与异常追踪 |
| 最大处理数量 | 1 / 10 / 100 | 防止误批量 |
| 商品来源 | 采集箱 / 待发布 / 外部导入 | 当前主路径推荐采集箱 |
| 店铺筛选 | Dang Kang | 必须与店铺配置一致 |
| 商品分组筛选 | 可选 | 防止扫错范围 |
| 领取标记 | AI认领 | 用于归属校验 |
| 备注颜色 | 红色 | 便于人工识别 |
| 执行模式 | 只保存 | 默认禁止发布 |

## 5.3 类目模板配置

示例：立牌类谷子。

| 字段 | 示例 |
|---|---|
| 目标类目名 | 立牌类谷子 |
| 英文类目名 | ACG Stand |
| 类目选择方式 | 类目 ID 优先，名称兜底 |
| 默认品牌 | None |

## 5.4 标题与文案配置

| 配置项 | 说明 |
|---|---|
| 标题来源 | 外部导入 / 模板拼接 / 系统规则生成 |
| 标题语言 | 英文 |
| 禁词表 | 平台禁词、侵权词、品牌词 |
| 长度限制 | 按速卖通标题长度限制 |
| 详情页模板 | PC / 无线详情模板 |
| 无线详情生成策略 | 使用模板、商品图、卖点字段生成 |

```text
Wind Breaker Anime Acrylic Keychain Hot Spring Battle Charm
```

## 5.5 SKU 与编码配置

SKU 策略应支持三种模式：

1. 沿用店小秘生成。
2. 用户自定义规则。
3. 系统预设规则。

推荐配置项：

| 配置项 | 示例 |
|---|---|
| SKU 前缀来源 | 店小秘生成 / 商品 ID / 任务前缀 |
| SKU 后缀规则 | 001, 002, 003... |
| 货品编码策略 | 默认等于 SKU |
| 商品编码策略 | 默认等于 SKU 或店小秘商品编码 |
| 条码策略 | 留空 / 外部表导入 / 使用 SKU |
| 重复 SKU 处理 | 自动校正 / 报错停止 |

示例：

```text
DXM104957400423001
DXM104957400423002
DXM104957400423003
```

## 5.8 图片配置

图片来源应按优先级配置，不能运行时随机猜。

推荐配置：

| 图片类型 | 来源策略 | 失败策略 |
|---|---|---|
| 主图 | 采集图 / 商品原图 | 缺失则报错 |
| 白底图 | 生成 / 图片银行 / 图片空间 | 缺失则报错或使用配置兜底 |
| 场景图 | 生成 / 图片银行 | 缺失可按配置跳过 |
| 详情图 | 商品图 / 详情模板 | 缺失则报错 |
| 产品本体标签图 | 图片银行 / 图片空间 / 本地图片 | 缺失则报错 |
| 外包装标签图 | 图片银行 / 图片空间 / 本地图片 | 缺失则报错 |

图片银行是可用入口，系统应支持：

```text
点击上传入口
→ 选择“图片银行（速卖通）”
→ 按目录 / 标签 / 最新 / 第一张 / 指定文件名选择图片
→ 确认
→ 校验图片已回填
```

图片空间可作为备选来源，但不能替代图片银行的正式配置。

# 6. 页面定位与自动化策略

## 6.1 定位优先级

执行器应按以下优先级定位页面元素：

1. URL 与页面标题。
2. 语义文本，例如 `保存`、`编辑半托管信息`、`图片银行（速卖通）`。
3. 表单 label，例如 `是否原箱`、`物流属性`、`JIT库存`。
4. 表格表头与行列关系，例如按 `颜色` 行匹配 `SKU编码` 列。
5. DOM class 与组件结构，例如 Ant Design `ant-select`、`ant-modal`。
6. 元素 bounding box 坐标。
7. 截图识别。

坐标只能作为兜底，不能作为主策略。

## 6.2 表格字段定位方式

变种表格必须通过“表头列名 + 行变种名”定位。

示例：

```text
行：白色(Stand 1)
列：SKU编码
值：DXM104957400423001
```

不推荐直接使用第几个 input，因为页面新增列、折叠列、滚动位置变化都会导致错填。

## 6.3 页面反馈校验

每个关键动作后必须读取至少一个权威反馈：

| 动作 | 推荐校验信号 |
|---|---|
| 备注提交 | 行内出现 `备注:AI认领` |
| 类目选择 | 类目路径或类目输入框显示目标类目 |
| 图片选择 | 目标图片槽出现新图片、尺寸文本或图片 URL |
| 模板选择 | 下拉框显示模板名 |
| 半托管勾选 | `编辑半托管信息` 按钮出现 |
| 进入半托管页 | URL 包含 `editFromSmt`，标题为编辑半托管 |
| 保存 | 接口返回 code=0，页面弹窗提示编辑成功 |

# 7. 详细操作流程

## 7.1 阶段 A：登录态与页面准备

目标：确认真实浏览器已登录店小秘，并关闭会阻挡操作的弹窗。

步骤：

1. 打开真实店小秘页面。
2. 检查是否已登录。
3. 如果未登录，暂停并提示用户在真实页面登录。
4. 登录成功后记录账号、店铺可见状态。
5. 检查公告、培训、产品动态等弹层。
6. 如存在非业务弹层，点击关闭。
7. 进入产品菜单或直接打开采集箱 URL。

成功条件：

- 页面可见 `产品`、`订单`、`客服` 等主导航。
- 当前账号处于登录态。
- 无遮挡操作的 modal 或 mask。

失败处理：

- 登录失效：进入异常池，类型 `登录失效`。
- 验证码：进入人工接管。
- 弹窗无法关闭：记录截图与 DOM，进入异常池。

## 7.2 阶段 B：进入速卖通采集箱

目标：进入速卖通采集箱并筛选目标商品。

路径：

```text
产品
→ 数据采集 / 速卖通
→ 采集箱
```

可直接使用已确认路径：

```text
/web/smt/smtProductList/draft
```

步骤：

1. 打开采集箱页面。
2. 确认页面标题或面包屑为速卖通采集箱。
3. 按任务配置筛选店铺。
4. 按任务配置筛选分组、状态、关键词或商品 ID。
5. 定位目标商品行。

成功条件：

- 目标商品行唯一。
- 商品标题、店铺、分组与任务一致。

失败处理：

- 未找到商品：进入异常池。
- 多条匹配：停止，要求任务配置更精确。
- 店铺不一致：停止，防止误操作。

## 7.3 阶段 C：领取与备注

目标：给当前商品写入任务归属标记，保证后续只操作自己领取的商品。

步骤：

1. 在目标商品行点击 `更多`。
2. 点击 `添加备注`。
3. 在备注弹窗填写内容，例如 `AI认领`。
4. 按配置选择备注颜色，例如红色。
5. 点击 `提交`。
6. 读取商品行回显，确认出现 `备注:AI认领`。

成功条件：

- 商品行出现配置的备注内容。
- 备注颜色符合配置，或至少备注文本回显成功。

失败处理：

- 找不到 `添加备注`：记录页面结构异常。
- 提交失败：读取错误提示并进入异常池。
- 行内未回显：刷新或重查一次；仍失败则停止。

## 7.4 阶段 D：进入普通商品编辑页

目标：进入普通编辑页并再次确认商品归属。

步骤：

1. 在目标商品行点击 `编辑`。
2. 等待商品编辑页加载。
3. 读取标题、店铺、商品 ID、SKU 等关键字段。
4. 校验商品仍是当前任务商品。
5. 保存编辑页初始截图与 DOM 快照。

成功条件：

- 编辑页加载完成。
- 页面商品与任务商品一致。

失败处理：

- 打开了错误商品：立即返回并停止。
- 编辑页加载失败：重试一次，仍失败则进入异常池。

## 7.5 阶段 E：填写类目

目标：选择或确认目标类目。

步骤：

1. 定位类目选择区域。
2. 如果已有类目，读取当前类目。
3. 若类目不符合任务配置，按类目模板重新选择。
4. 选择 `立牌类谷子 / ACG Stand`。
5. 等待类目属性刷新。
6. 校验类目路径或类目 ID。

成功条件：

- 页面显示目标类目。
- 类目属性区刷新完成。

失败处理：

- 类目无权限：进入异常池，类型 `类目权限异常`。
- 类目不存在：进入异常池，类型 `类目配置错误`。
- 属性未加载：重试刷新属性区。

## 7.6 阶段 F：填写标题与基础信息

目标：按配置写入标题与基础字段。

步骤：

1. 定位标题输入框。
2. 写入 `title_final`。
3. 校验标题长度、禁词、语言。
4. 填写或确认基础字段：
   - 品牌
   - 材质
   - 尺寸
   - 是否 IP 授权
   - 是否定制
   - 是否礼物
   - 是否专利供应
5. 对无真实依据字段使用模板默认值，例如 `None`、`No`、`Other`。

成功条件：

- 标题显示正确。
- 必填基础属性均有值。

失败处理：

- 命中禁词：停止并进入异常池。
- 必填属性无配置：停止并记录缺失字段。

## 7.7 阶段 G：填写产品信息与变种表格

目标：填写 SKU、价格、库存、重量、尺寸、是否原箱、物流属性、商品编码等字段。

字段示例：

| 颜色 | 零售价 | 货值 | 库存 | 重量 | 长 | 宽 | 高 | 是否原箱 | 物流属性 | 商品编码 |
|---|---:|---:|---:|---:|---:|---:|---:|---|---|---|
| 白色(Stand 1) | 7.01 | 1 | 200 | 0.03 | 10 | 10 | 2 | 否 | 普货 | DXM...001 |

目标：按图片配置为页面各图片槽位选择图片。

```text
点击图片槽位 / 上传按钮
→ 展开上传来源菜单
→ 点击“空间图片”
→ 在图片空间弹窗中选择图片
→ 点击确定
→ 校验图片槽位已回填
```

图片选择规则应配置化：

- 指定图片 ID。
- 指定目录。
- 指定文件名关键词。
- 指定标签。
- 最新一张。
- 第一张可用图片。

步骤：

1. 主图：确认或补齐。
2. 白底图：上传或生成。
3. 场景图：上传或生成。

成功条件：

- 每个必需图片槽位显示图片。
- 如页面显示尺寸，尺寸应符合配置要求。

失败处理：

- 图片银行无响应：按配置选择重试、切换图片空间或进入异常池。
- 图片格式不合规：进入异常池。
- 图片槽位未回填：重试一次，仍失败则停止。

## 7.10 阶段 J：填写详情与合规字段

- 返回校验错误：解析错误字段，进入异常池。
- 出现发布确认：立即停止。

# 11. 对系统实现的建议

## 11.1 配置中心优先

系统能力的核心不是“点击页面”，而是配置中心。

必须优先建模：

- 店铺模板
- 类目模板
- 标题模板
- 图片模板
- 价格模板
- SKU 模板
- 物流模板
- 合规模板
- 半托管模板
- 异常处理策略

## 11.2 执行器按状态机运行

推荐状态机：

```text
INIT
→ CHECK_LOGIN
→ OPEN_DRAFT_LIST
→ FIND_PRODUCT
→ CLAIM_PRODUCT
→ OPEN_EDIT_PAGE
→ FILL_BASE_INFO
→ FILL_VARIANTS
→ FILL_MEDIA
→ FILL_COMPLIANCE
→ ENABLE_SEMI_MANAGED
→ OPEN_SEMI_MANAGED_PAGE
→ FILL_SEMI_GOODS
→ FILL_SEMI_VARIANTS
→ SAVE_ONLY
→ VERIFY_RESULT
→ DONE
```

失败统一转入：

```text
FAILED
→ CAPTURE_EVIDENCE
→ WRITE_EXCEPTION
→ STOP_OR_NEXT_PRODUCT
```

## 11.3 DOM 为主，截图为证据

正式系统建议：

- DOM 定位用于主操作。
- 网络接口返回用于保存确认。
- 截图用于审计、异常分析、人工复核。
- 坐标点击只作为兜底，并且坐标应来自 DOM 元素 bounding box，而不是写死屏幕位置。

## 11.4 页面适配可热更新

店小秘页面可能变化，选择器不应写死在代码里。

建议配置：

```yaml
pages:
  smt_draft_list:
    url_contains: "/web/smt/smtProductList/draft"
    product_row_match:
      - title
      - store
      - remark
  smt_edit:
    save_button_text: "保存"
    semi_managed_button_text: "编辑半托管信息"
  smt_semi_edit:
    url_contains: "editFromSmt"
    save_button_text: "保存"
    forbidden_buttons:
      - "立即发布"
      - "发布"
```

## 11.5 不把 AI 放在执行闭环里

AI 可以用于：

- 根据真实页面整理字段映射。
- 辅助生成配置模板。
- 分析失败日志。
- 总结异常原因。
- 帮用户设计规则。

AI 不应在正式批量任务运行时临场决定：

- 选哪个类目。
- 填哪个品牌。
- 是否伪造条码。
- 是否继续发布。
- 页面错误是否忽略。

正式运行应是确定性程序。

9. 异常池 UI 与一键重试规则。

---

# 14. 最终原则

这套系统要做成“配置驱动的店小秘自动刊登执行器”，不是一次性脚本。

正确方向：

```text
字段先建模
模板先配置
页面按状态机执行
每步可校验
失败可追溯
发布强隔离
保存可闭环
```

只有这样，才能从单次跑通变成可稳定批量执行的自动化产品。
