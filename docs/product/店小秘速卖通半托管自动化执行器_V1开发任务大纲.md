# 店小秘速卖通半托管自动化执行器 V1 开发任务大纲

> 版本：v0.1  
> 日期：2026-05-20  
> 依据：PRD V1.0、技术选型与系统架构文档 V1.0、半托管自动化操作流程参考版  
> 开发原则：配置先行、状态机执行、商品归属锁、发布强隔离、只保存到待发布、失败进入异常池。

---

## 1. V1 总目标

V1 要把当前可运行原型推进到“单商品半托管保存闭环可验证、小批量串行可控”的本地自动化执行器。

最终 V1 链路：

```text
配置预检
→ 登录态检查
→ 进入速卖通采集箱
→ 定位目标商品
→ 领取并写入任务唯一标记
→ 打开普通编辑页并复核归属
→ 填写普通商品信息
→ 勾选半托管参与
→ 进入半托管编辑页
→ 填写半托管信息
→ 只点击保存
→ 校验保存成功且未发布
→ 生成证据、异常、报告
```

V1 明确不做：

- 自动发布、继续发布、保存并发布。
- 绕过验证码。
- 无依据伪造品牌授权、合规资质、真实条码。
- 多平台、多店铺并发。
- 全托管正式执行。

## 3. 开发里程碑

### M0：需求与安全边界冻结

目标：把 PRD、技术架构、操作流程转成开发可执行契约。

任务：

- 固化执行模式：`probe`、`dry_run`、`claim_only`、`single_save`、`batch_save`。
- 永久禁止模式：`publish`、`continue_publish`、`save_and_publish`。
- 固化异常码：E101 到 E999。
- 固化状态节点契约。
- 固化发布隔离规则。
- 固化商品归属锁规则。

验收：

- 代码中存在状态契约、发布隔离器、归属锁基础服务。
- 单元测试覆盖发布风险判断、锁冲突、状态节点契约。

### M1：配置中心最小版

目标：运行前配置完整，不在执行中临时判断关键字段。

任务：

- 店铺配置。
- 任务配置。
- 类目模板。
- SKU / 编码规则。
- 价格库存规则。
- 包装物流模板。
- 图片规则。
- 合规模板。
- 半托管模板。
- 发布禁用规则。
- 启动前配置完整性检查。

验收：

- 能创建一条 `single_save` 任务。
- 缺少必填模板时无法启动。
- 前端不提供发布模式。

### M2：探测器、证据与商品归属锁

目标：真实浏览器只探测、只领取、只操作自己锁定的商品。

任务：

- 登录态检查。
- 弹窗关闭。
- 进入采集箱。
- 商品行定位。
- 写入任务唯一领取标记。
- 行内备注回读校验。
- 编辑页归属复核。
- 证据采集：截图、DOM、URL、标题。

验收：

- 非当前任务商品不编辑。
- 没有当前任务标记不编辑。
- 每个关键节点有证据记录。

### M3：普通编辑页单品流程

目标：普通编辑页可按配置补齐半托管前置字段。

任务：

- 类目选择与校验。
- 标题与基础属性填写。
- 变种表格按“表头 + 行名”定位。
- 价格、货值、库存、重量、尺寸、是否原箱、物流属性、商品编码填写。
- 运费模板、服务模板选择。
- 图片银行选择与回填校验。
- 详情与合规字段按配置填写。
- 勾选半托管参与。

验收：

- 普通编辑页字段通过页面校验。
- 出现 `编辑半托管信息` 按钮。
- 出错时进入异常池，不强行继续。

### M4：半托管页保存闭环

目标：半托管信息完整填写并只保存到待发布。

任务：

- 进入半托管编辑页。
- 参加国家策略。
- 是否原箱、物流属性、重量、尺寸。
- 半托管价格、SKU、货品编码、货品条码策略、JIT 库存。
- 保存前发布隔离复核。
- 点击保存。
- 读取接口返回和页面提示。
- 保存后验证 `published=false`。

验收：

- 保存成功。
- 报告记录“未发布”证明。
- 任何发布确认或发布按钮目标都会触发 E999。

### M5：异常池与执行报告

目标：失败可定位，成功可复核。

任务：

- 异常池列表与详情。
- 异常建议。
- 证据面板。
- 商品报告。
- 任务汇总报告。
- 报告导出。

验收：

- 任一失败项可看到状态、原因、截图、DOM、网络摘要。
- 成功项报告包含未填写字段、填写字段、保存结果、未发布证明。

### M6：小批量串行保存

目标：5 到 10 条商品串行执行，失败不影响后续商品。

任务：

- `batch_save` 模式。
- 单浏览器、单任务、单商品串行。
- 断点续跑。
- 跳过当前商品。
- 小批量报告汇总。

验收：

- 并发数固定为 1。
- 每条商品独立锁、独立证据、独立报告。
- 无误操作、无误发布。

## 4. 第一轮开发切片

第一轮只做 P0 基础设施，不接真实店小秘编辑动作。

范围：

1. 发布隔离器 `PublishGuardService`。
2. 商品归属锁 `OwnershipLockService`。
3. 状态节点契约 `state_contracts`。
4. V1 开发任务大纲文档。
5. 单元测试覆盖上述基础模块。

不做：

- 不点击店小秘页面。
- 不实现真实普通编辑页字段填写。
- 不实现真实半托管保存。
- 不改发布相关 UI。

验收：

- 发布相关动作和文本会被阻断。
- 任务唯一领取标记能生成和入库。
- 同一商品被其他未释放任务锁定时会冲突。
- V1 状态节点具备前置条件、动作、期望结果、失败码、证据要求。
- 后端测试一轮通过。

## 5. P0 详细任务

### P0-1 发布隔离器

输入：

- 执行动作。
- 目标按钮文本。
- 当前 URL。
- 可见按钮文本。
- 弹窗文本。
- 网络请求 URL。

输出：

- `allowed`。
- `risk_level`。
- `error_code`。
- `reasons`。

必须阻断：

- `立即发布`
- `发布`
- `继续发布`
- `保存并发布`
- `确认发布`
- `提交发布`
- `publish`
- `release`
- `online`
- `submitPublish`

### P0-2 商品归属锁

锁字段：

- `task_id`
- `job_id`
- `product_id`
- `store_name`
- `source_title`
- `sku_prefix`
- `lock_owner_run_id`
- `lock_token`
- `lock_status`
- `lock_expires_at`
- `page_claim_mark`
- `page_claim_verified`
- `ownership_fingerprint`

领取标记规则：

```text
AI认领-{task_id}
```

默认不使用泛化 `AI认领` 作为唯一锁。

### P0-3 状态节点契约

每个状态节点必须包含：

- `state_name`
- `preconditions`
- `actions`
- `expected_url`
- `expected_text`
- `expected_dom`
- `expected_network`
- `retry_policy`
- `failure_code`
- `evidence_required`
- `publish_guard_required`
- `ownership_required`

### P0-4 测试

只做一轮后端测试：

```powershell
cd app/backend
.\.venv\Scripts\python.exe -m pytest tests -q
```

## 6. 后续开发顺序

1. P0 安全基础设施。
2. M1 配置中心最小版。
3. M2 探测器、证据、领取。
4. M3 普通编辑页适配。
5. M4 半托管页保存。
6. M5 异常池与报告。
7. M6 小批量串行。

每个阶段都先保证：

- 不发布。
- 不误操作非当前任务商品。
- 失败有证据。
- 页面动作可复核。
