# 店小秘半托管执行器可交付化回归矩阵

更新时间：2026-07-22

## 交付基线

- 产品入口：店小秘商品箱中的现有商品。
- 真实 mutation：`single_save` 与 `controlled_edit_batch`；均只保存、不发布。
- 已移除：认领页面、认领任务/API/状态机和旧流程验收字段。
- 始终禁止：旧 `batch_save`、无人值守调度、发布、继续发布、保存并发布、移入待发布。
- 当前生产状态以同 HEAD 最新交付证据为准；没有新包和现场证据时保持 `BLOCKED`。

## 不可退化项

| 领域 | 不可退化要求 |
|---|---|
| 商品箱身份 | 保存任务创建时冻结 product/store/source/target/evidence 快照；任一漂移停止。 |
| 店铺边界 | 任务、冻结快照和实时页面店铺必须一致，不得硬编码或跨店复用。 |
| 批次范围 | 受控整批只能使用批准时冻结的可见范围和顺序，不得运行中扩容。 |
| 人工批准 | 单次保存消费服务端批准；整批一次批准后每项使用短时一次性 grant。 |
| 发布隔离 | 任意发布按钮、弹窗、URL 或网络信号都必须停止。 |
| 模板完整性 | required 模板或字段未命中时不得进入保存。 |
| 保存证据 | 精确保存回包、页面成功、保存截图和独立未发布证明必须同时存在。 |
| 状态一致性 | task/job/report/exception 矛盾阻断 READY；late result 不得覆盖人工复核或新状态。 |
| Mutation ledger | `DISPATCHING` 崩溃恢复为 `UNKNOWN`；`UNKNOWN`/`DISPATCHED` 不自动重试。 |
| 实时身份 | 点击前重查 runtime、session、页面、冻结目标、批准和 lifecycle owner。 |

## 四级回归

| 等级 | 目标 | 访问店小秘 | 写入 | 通过标准 |
|---|---|---:|---:|---|
| L0 | 代码回归 | 否 | 否 | 后端测试、前端测试/build、脚本契约全绿。 |
| L1 | 离线 DOM replay | 否 | 否 | selector replay 通过；危险按钮不进入动作映射。 |
| L2 | 商品箱真实只读检查 | 是 | 否 | `draft_box` 登录态、路径、binding、文件 hash 和全部零写计数通过。 |
| L3 | 单商品只保存金丝雀 | 是 | 是 | 商品箱快照有效、批准已消费、精确保存成功、独立未发布证明、ledger 已对账。 |
| 批次验收 | 受控整批 | 是 | 是 | 一次批准、全局单并发、严格串行、逐商品 L3 证据、失败隔离、`UNKNOWN` 停批。 |

## 真实 L3 执行前检查

- 新鲜商品箱 L2 为 `passed`，且 binding 属于当前脚本、session、Git HEAD。
- 任务模式为 `single_save`，发布场景为 `SMT_SEMI_MANAGED_SAVE_ONLY`。
- `product_box_snapshot` 和 fingerprint 完整，证据文件仍存在且 hash 一致。
- 服务端批准租约有效，保存动作前会被原子消费。
- required 模板、图片和半托管字段配置完整。
- 发布隔离预检通过。
- Browser Agent 实时 session/page/target、lifecycle owner 与 ledger 状态有效。
- ledger 中无同一动作的 `DISPATCHING`、`UNKNOWN` 或未完成记录。

## 单次保存验收

`dxm_single_save_acceptance.v1` 必须满足：

- `passed=true`、`status=passed`、`missing_codes=[]`；
- `product_box_snapshot_error=null`；
- 所有 checks 为严格 Boolean `true`；
- `save_report_count>=1`、`evidence_count>=2`；
- `dxm_state_consistency.v1` 无 violation。

报告顶层 `published=false` 不是独立未发布证明；必须有保存之后采集、同目标绑定且不复用保存文件的结构化读回。

## 最终交付门禁

- 后端全量测试、前端生产 build、桌面 build 和脚本契约通过。
- L1 通过；L2 只有一个真实 `draft_box` 目标并严格验证 binding/freshness/hash/path。
- L3 使用当前 portable、当前商品箱商品和当前批准产生。
- `delivery_readiness.ready=true`。
- `single_save_acceptance.passed=true`。
- `state_consistency.consistent=true`。
- ledger 无 `UNKNOWN`/未对账动作。
- git 工作区干净；runtime/build/portable/验收报告指向同一 HEAD，并记录 portable SHA-256。
- 若声明 `controlled_edit_batch` 可交付，必须另有批次级串行、逐项证据和停批对账验收。
