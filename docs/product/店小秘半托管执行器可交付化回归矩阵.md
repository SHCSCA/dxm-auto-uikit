# 店小秘半托管执行器可交付化回归矩阵

## 交付基线

- 基线提交：`ca415eb feat: add dxm reference template mapping`
- 交付模式：本地/内网工作台，配置驱动，状态机执行；当前真实保存受 L2/L3 门禁阻断。
- 设计支持模式：`probe`、`dry_run`、`claim_only`、`single_save`、`batch_save`；当前真实 `claim_only` / `single_save` / `batch_save` 受 L2/L3 门禁阻断，不等同于已可用。
- 禁止动作：发布、立即发布、继续发布、保存并发布、保存并移入待发布、移入待发布
- 真实写入边界：L3 `single_save` 只允许在真实 L2 双目标通过且人工明确批准后执行。

## 不可退化项

| 领域 | 不可退化要求 |
| --- | --- |
| 店铺边界 | 真实任务只允许操作 Dang Kang，其他店铺必须停止。 |
| 商品归属 | 只能操作当前任务领取并带有 `AI认领-{task_id}-{job_id}` 的商品。 |
| 发布隔离 | 任意发布相关按钮、弹窗、URL、网络请求信号都必须 E999 停止。 |
| 模板完整性 | `dxm_reference_templates` required 分区缺名称或页面未命中时不得进入保存。 |
| 图片证据 | 欧盟外包装图必须证明使用了配置文件名；营销图必须证明白底处理。 |
| 保存证据 | 保存成功、`published=false`、未发布校验截图必须同时存在。 |
| 报告证据 | report summary 必须保留 workflow results、模板解析、保存结果和证据路径。 |

## 重点真实页面证据

### 欧盟外包装图

- 配置来源：`image.eu_outer_package_filename`
- 必须记录：图片银行搜索词、选中图片文本、选中项缩略图状态、槽位回填后状态。
- 通过标准：选中项文件名与配置文件名一致，或结果中明确 `filename_matched=true`。

### 营销图白底

- 策略：`marketing_images_strategy=generate`
- 必须记录：生成前营销图状态、生成后 1:1/3:4 图片状态、图片工具菜单中“图片白底”、白底弹窗“一键白底”点击结果。
- 通过标准：`1:1白底图` 与 `3:4场景图` 均有图片，且白底处理结果为成功或已处理。

### 店小秘引用模板

- 必须记录：`dxm_reference_templates_resolved` 和 `dxm_reference_template_results`
- 通过标准：required section 均 `ok=true`；optional 未命中必须记录 reason，不能静默消失。

### 保存与未发布证明

- 必须记录：保存按钮定位结果、保存成功文案、保存相关接口响应或 HAR 摘要、未发布校验截图。
- 证据等级：
  - A：页面截图 + report `published=false` + 保存接口/HAR + 无 publish 网络。
  - B：页面截图 + report `published=false`，但未捕获保存接口。
  - C：缺保存截图或缺未发布校验，不可交付。

## 真实 L3 执行前检查

- 用户明确确认允许真实写入。
- L2 `data_acquisition` 与 `draft_box` 最新真实只读 probe 均为 `passed`，且来自同一 `evidence_binding.run_id` / session / script / git head。
- 当前登录态有效，且无需绕过验证码。
- 任务模式为 `single_save`，发布场景为 `SMT_SEMI_MANAGED_SAVE_ONLY`。
- 店铺为 Dang Kang。
- 商品为当前任务白名单商品。
- 采集箱目标行已有当前任务唯一备注。
- 所有 required 模板、图片、半托管字段配置通过。
- 发布隔离预检通过。

## 最终交付门禁

- 后端 `pytest -q` 全绿。
- 前端 `npm run build` 通过。
- L0/L1 回归完成，且工作台 L1 显示 `passed`。
- L2 只读 probe 有双目标真实通过记录，并共享同轮次 evidence binding；若只存在 mock 证据，工作台必须显示“离线证据/不满足真实页面 L2 放行条件”；若只有单目标通过，必须显示“部分完成”；任一真实目标失败、缺失 binding 或 binding 不一致必须显示失败并阻断 L3。
- L3 单商品金丝雀有最新验收记录，或在 L2 未通过时明确标记为阻断；不得只凭人工批准进入真实写操作。
- 前端原型经用户确认。
- git 工作区干净并提交。
