# DXM Agent Console 生产级版本计划

更新日期：2026-06-24

## 1. 产品定位

DXM Agent Console 的交付目标不是测试工具、诊断台或本地演示台，而是面向普通运营用户的真实店小秘自动化控制台。

核心流程固定为两大段：

1. **数据采集认领**：在真实店小秘浏览器中，从数据采集页把目标商品认领到采集箱。
2. **采集箱编辑保存**：在真实店小秘浏览器中，从采集箱打开商品编辑页，按模板填写并只点击保存。

本阶段明确不开放：

- 发布
- 保存并发布
- 移入待发布
- 批量保存
- 无人值守自动发布
- 绕过采集箱的本地测试商品保存

## 2. 当前状态评估

按当前 `feature/dxm-production-two-stage` 分支估算，项目整体距离“生产级可交付”约 **65% - 70%**。

| 模块 | 当前进度 | 状态判断 |
| --- | ---: | --- |
| 产品导航与首页路径 | 85% | 业务菜单已收敛到首页、店小秘登录、数据采集认领、采集箱编辑保存、模板中心、执行浏览器、结果与问题；仍需真实流程回归 |
| 数据采集认领 | 65% | 后端与页面已有雏形，需要真实店小秘从采集页认领到采集箱的完整验收 |
| 采集箱编辑保存 | 70% | 单商品只保存能力已有基础，需与“认领成功商品”强绑定并重跑真实保存验收 |
| 模板中心 | 60% | 已改为模板中心和预置配置模板口径；多模板管理、保存反馈、执行取值预览仍需打磨 |
| 真实浏览器 Agent 与 HUD | 25% | 需求已明确，尚需常驻 HUD、生命周期守护、异常恢复和中文步骤映射 |
| 日志与结果问题 | 35% | 当前日志仍偏工程化，需改成用户能理解的业务事件和恢复动作 |
| 免安装 EXE | 90% | 当前分支已重新打包、验证并覆盖交付目录；剩余风险是随最终真实验收后再次出包 |
| 真实验收证据 | 30% | 历史有受控保存证据，本轮两段式流程还未形成最终验收报告 |

结论：当前版本不能标记为最终可交付，只能算“生产化改造中间态”。

## 3. 版本路线

### V0.9 方向修正版

目标：把产品从“测试/诊断工作台”改回正确业务方向。

交付内容：

- 主流程改为两段式：数据采集认领、采集箱编辑保存。
- 移除默认路径中的测试商品、QA 商品、本地商品概念。
- 菜单以普通用户动作命名，不再让用户理解 `claim_only`、`single_save`、L2、L3。
- 发布、批量、无人值守保持关闭。

完成标准：

- 用户打开软件能看懂“先认领，再编辑保存”。
- 首页只提示当前要做什么、为什么不能继续、下一步点哪里。
- 技术诊断默认隐藏。

当前状态：基本完成，需要跟随 UI 回归继续修正。

### V1.0 单店单品可用版

目标：让一个普通运营用户能完成单店、单商品、只保存的完整真实流程。

交付内容：

- 店小秘账号登录和本机加密记住账号密码。
- 显式启动真实浏览器。
- 从数据采集页认领 1 个真实商品到采集箱。
- 从采集箱打开该商品编辑页。
- 使用一个确认后的模板填写。
- 人工确认后只点击保存。
- 生成保存成功和未发布证明。

完成标准：

- 不需要开发者命令行操作。
- 用户不用理解技术门禁。
- 出错时能看到中文原因和恢复按钮。
- 至少完成 1 次真实店小秘端到端验收。

这是第一版真正可以给客户试用的最低版本。

### V1.1 数据采集认领增强版

目标：把第一段“认领到采集箱”做成稳定、可解释、可恢复的功能。

交付内容：

- 认领任务创建页：
  - 选择店铺
  - 选择平台
  - 输入采集关键词或商品线索
  - 填写认领标记
- 真实浏览器执行：
  - 打开数据采集页
  - 搜索或定位商品
  - 点击认领到采集箱
  - 检查采集箱是否出现该商品
- 认领结果记录：
  - 店铺
  - 平台
  - 商品标题
  - 来源链接
  - 采集箱标题
  - 认领时间
  - 证据截图
  - 失败原因

完成标准：

- 认领成功后，第二段页面能直接选择该商品。
- 认领失败时，用户知道是没有找到商品、未登录、页面变化、权限问题，还是需要人工接管。
- 认领阶段不执行保存、不发布。

### V1.2 采集箱编辑保存增强版

目标：把第二段“采集箱编辑并只保存”做成可靠生产路径。

交付内容：

- 只能从已认领商品开始编辑保存。
- 保存前展示：
  - 商品
  - 店铺
  - 模板
  - 将填写的分区
  - 本次不会发布
- 编辑页填写：
  - 店铺与任务基础
  - 类目与标题
  - SKU / 价格 / 库存
  - 图片与素材
  - 包装物流
  - 合规 / 海关
  - 半托管
  - 店小秘引用模板
- 保存动作：
  - 只点击保存
  - 检查保存成功响应
  - 检查未发布状态

完成标准：

- 保存成功必须有网络响应或页面成功提示证据。
- 未发布证明必须独立存在。
- 页面出现发布类按钮时不误点。
- 如果保存失败，结果页必须给出可执行恢复建议。

### V1.3 模板中心生产版

目标：把“配置中心”升级为客户能长期使用的多模板系统。

交付内容：

- 模板列表：
  - 新建模板
  - 复制模板
  - 重命名模板
  - 删除模板
  - 启用模板
  - 设为店铺默认
  - 设为类目默认
- 分区表单：
  - 每次只展开一个分区
  - 字段全部中文
  - 必填项明确
  - 保存状态明确
  - 未保存修改明确
- 执行取值：
  - 本次任务覆盖
  - 当前选择模板
  - 类目默认模板
  - 店铺默认模板
  - 系统默认模板
- 预置配置模板：
  - 只能作为示例/起步模板
  - 不能伪装成真实客户数据
  - 执行前必须让用户确认

完成标准：

- 用户能回答“当前用的是哪套模板”。
- 用户能回答“我刚填的信息有没有保存”。
- 用户能回答“执行时到底会用哪个值”。
- 英文字段 key 不暴露在普通用户路径里。

### V1.4 真实浏览器 Agent 稳定版

目标：让真实浏览器成为可观察、可接管、不会黑盒闪退的执行现场。

交付内容：

- 浏览器窗口显式打开并常开。
- 浏览器左上角常驻中文 HUD。
- HUD 内容：
  - 当前任务
  - 当前阶段
  - 当前步骤
  - 正在做什么
  - 是否需要用户接管
  - 失败原因
- HUD 在页面跳转后自动重注入。
- Agent 异常退出时主窗口提示：
  - 发生了什么
  - 为什么停止
  - 下一步怎么恢复
- 浏览器可人工接管：
  - 用户可修正验证码
  - 用户可修正页面异常
  - 用户可回到控制台继续

完成标准：

- 浏览器不能“跑一下就闪退且没有结果”。
- HUD 不能运行到一半消失。
- 任务失败不能只显示原始异常。
- 主窗口、浏览器 HUD、结果与问题三处状态必须一致。

### V1.5 日志与结果问题生产版

目标：把日志从工程输出改成客户可理解的操作记录。

交付内容：

- 默认日志只显示关键业务事件：
  - 已打开真实浏览器
  - 已进入数据采集
  - 已找到商品
  - 已认领到采集箱
  - 已打开编辑页
  - 正在填写标题
  - 正在处理图片
  - 正在只保存
  - 保存成功
  - 已确认未发布
- 原始日志只放到维护人员诊断。
- 每个失败都统一成：
  - 发生了什么
  - 为什么会停止
  - 下一步怎么做
  - 维护人员详情

完成标准：

- 普通用户不看到 `greenlet`、`Internal Server Error`、`HAR`、`run-id` 这类词。
- 日志不重叠、不遮挡、不刷屏。
- 结果与问题页能按用户动作恢复，而不是只让用户看日志。

### V1.6 免安装交付版

目标：输出真正能发给客户使用的免安装 Windows 包。

交付内容：

- 一个主 EXE 启动控制台。
- 不再弹出两个服务窗口作为用户操作入口。
- 自动托管后端、前端、浏览器 Agent。
- 交付目录包含：
  - `DXM-Agent-Console.exe`
  - `resources`
  - `快速使用说明.md`
  - `故障处理说明.md`
  - `验收报告.json`
  - `版本说明.md`
- 启动前自检：
  - 端口占用
  - 依赖缺失
  - resources 缺失
  - 浏览器依赖缺失
  - 数据目录可写

完成标准：

- 用户双击 EXE 即可进入主控制台。
- 登录信息可本机加密保存。
- 本轮分支重新打包，不沿用历史包冒充新版本。
- 真实流程验收通过后再输出最终路径。

## 4. 菜单栏最终设计

### 一级菜单

建议最终侧边栏采用 7 个入口：

1. **首页**
2. **店小秘登录**
3. **数据采集认领**
4. **采集箱编辑保存**
5. **模板中心**
6. **执行浏览器**
7. **结果与问题**

### 二级能力归属

| 一级菜单 | 下属能力 | 说明 |
| --- | --- | --- |
| 首页 | 当前步骤、阻断原因、下一步按钮、最近结果 | 只做决策，不堆配置和日志 |
| 店小秘登录 | 账号密码、本机记住、打开登录页、检测登录状态 | 用户先解决登录，不混入任务配置 |
| 数据采集认领 | 店铺平台、采集线索、认领标记、启动认领、认领结果 | 第一段业务闭环 |
| 采集箱编辑保存 | 选择已认领商品、确认模板、人工确认、启动保存、保存结果 | 第二段业务闭环 |
| 模板中心 | 模板列表、分区表单、默认模板、执行取值预览 | 长期配置管理 |
| 执行浏览器 | 浏览器状态、HUD 状态、Agent 生命周期、人工接管 | 只处理真实浏览器执行现场 |
| 结果与问题 | 保存报告、未发布证明、失败恢复、维护诊断 | 复盘和售后处理 |

不建议再单独保留：

- `证据中心`：普通用户不理解，合并进结果与问题。
- `异常池`：普通用户不理解，合并进结果与问题。
- `Agent 控制台`：太技术化，改成执行浏览器。
- `配置中心`：太泛，改成模板中心。
- `任务中心`：容易让用户先选本地商品，拆进数据采集认领和采集箱编辑保存。

## 5. 主窗口页面原则

每个页面只允许有一个主动作。

页面结构统一为：

1. 页面标题：用户当前在做哪件事。
2. 状态摘要：现在能不能继续。
3. 主按钮：下一步该点哪里。
4. 必要表单：只展示当前步骤需要填的字段。
5. 折叠详情：技术状态、日志、证据、路径。

禁止默认展示：

- 大段技术说明
- 原始日志刷屏
- 证据路径
- run-id
- L2/L3
- API 错误原文
- 大量同时展开的配置分区

## 6. 关键验收场景

### 场景 A：首次使用

1. 用户打开 EXE。
2. 首页提示先登录店小秘。
3. 用户填写账号密码并勾选记住。
4. 打开真实浏览器完成登录或验证码。
5. 主窗口显示店小秘已登录。

通过标准：用户不需要看日志也知道登录是否完成。

### 场景 B：采集认领

1. 用户进入数据采集认领。
2. 选择店铺和平台。
3. 输入商品线索。
4. 点击开始认领。
5. 真实浏览器打开数据采集页。
6. HUD 显示正在搜索、正在认领、正在确认采集箱。
7. 认领成功后生成可编辑商品。

通过标准：第二段能选择该商品。

### 场景 C：编辑保存

1. 用户进入采集箱编辑保存。
2. 选择已认领商品。
3. 确认模板。
4. 点击申请并启动单商品只保存。
5. 真实浏览器打开编辑页并填写。
6. Agent 只点击保存。
7. 结果显示保存成功、未发布。

通过标准：报告包含保存成功证据和未发布证明。

### 场景 D：失败恢复

1. 浏览器页面变化、验证码、权限或商品找不到。
2. 主窗口显示中文失败卡片。
3. 用户看到下一步操作。
4. 用户可人工接管浏览器。
5. 修正后可继续或重新创建任务。

通过标准：不出现只有技术错误、无法判断下一步的死局。

## 7. 最终交付门槛

项目只有同时满足以下 10 项，才算真正完成：

1. 两段式真实流程成立：数据采集认领到采集箱，再从采集箱编辑保存。
2. 不再依赖本地测试商品走主流程。
3. 真实浏览器显式常开，用户能看到操作。
4. 浏览器 HUD 常驻，不因跳转丢失。
5. 模板中心支持多套模板、中文分区、保存反馈、执行取值预览。
6. 普通用户路径没有技术术语干扰。
7. 所有失败都有中文恢复动作。
8. 发布、批量、无人值守仍被 UI 和 API 双层阻断。
9. 免安装 EXE 从当前分支重新打包并可启动。
10. 完成一轮真实店小秘端到端验收并保存报告。

## 8. 交付优先级

### P0 必须先完成

- 修复两段式流程和任务模型。
- 修复真实浏览器闪退和 HUD 消失。
- 修复用户看不懂的错误提示。
- 修复主流程还引用测试商品的问题。
- 修复免安装版 resources、启动、端口、自检问题。

### P1 紧随其后

- 模板中心多模板能力。
- 配置分区表单体验。
- 日志和结果与问题页。
- 保存结果和未发布证明。
- 首页和菜单最终收敛。

### P2 可在可交付后继续

- 批量导入商品线索。
- 多店铺批次管理。
- 角色权限。
- 自动更新。
- 更完整的运行统计。

## 9. 预计执行顺序

1. **先修流程模型**：认领任务与保存任务彻底拆开。
2. **再修浏览器 Agent**：常开、HUD、异常恢复。
3. **再修页面主路径**：菜单、首页、两段页面。
4. **再修模板中心**：多模板、分区、保存状态。
5. **再修日志和结果与问题**：用户语言、恢复动作、维护诊断。
6. **最后打包验收**：免安装 EXE、真实流程、文档报告。

## 10. 当前下一步

下一步应继续推进 **V1.4 真实浏览器 Agent 稳定版**，原因是：

- 用户已经明确要求真实浏览器必须显式常开。
- 当前最大交付风险是浏览器 Agent 闪退、HUD 消失、状态不一致。
- 如果浏览器执行现场不稳定，前面的页面和模板体验都无法真正交付。

具体下一步开发项：

1. 新增浏览器 Agent 中文状态映射服务。
2. 把 runner 的每个动作映射成用户看得懂的 HUD 文案。
3. 在页面跳转后自动重注入 HUD。
4. 浏览器 Agent 异常退出时保留现场并回传原因。
5. 主窗口显示统一状态，不再出现“浏览器已登录但控制台未通过”的矛盾。
6. 用真实浏览器验证 HUD 是否常驻。
