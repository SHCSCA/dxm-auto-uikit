# 普货方案配置与完整商品编辑执行架构

**产品裁决：视频、翻译、批发、半托管和 rollback preparation 是每件商品无条件必经的主流程。**
**当前实现：上述能力尚未全部进入正式 Runner/BrowserAgent/证据链，真实执行保持 `E3_OPEN / BLOCKED`，不是 `MVP_READY`，不是 `PROD_READY`。**

本文定义本地方案如何把当前会话、类目目录、店小秘模板、完整编辑配置和安全策略冻结为逐商品执行输入。它不把 Path A canary 冒充完整产品，也不把“产品必须具备”写成“当前代码已经完成”。

关联：[MVP 主合同](MVP-竖切-草稿箱批量只保存.md) · [DXM-TX 上游事实合同](../integration/DXM-TX-上游事实合同.md) · [当前运行时架构](../architecture/当前运行时架构.md) · [待关闭门禁](../../BLOCKED.md)。

## 1. 完整产品不变量

1. 每个方案绑定当前账号、一个店铺作用域和一个目标可执行叶子类目。
2. 每件商品必须无条件执行视频、翻译、批发、半托管和 rollback preparation；配置只能决定真实模式和值，不能关闭或跳过阶段。
3. 任一必经能力不受支持、缺稳定 binding、缺真实值、缺 readback 或缺证据合同时，必须在首个页面写入前 fail-closed。
4. 不允许回退 Path A、继承原值、空操作、`SKIPPED_BY_FROZEN_PLAN` 或禁用成功来冒充完整商品成功。
5. 完整执行路径是主编辑页 + 半托管页的 Path B 双阶段保存；Path A 只能作为工程切片/canary，不满足产品 READY。
6. 只允许精确识别的半托管中间“继续发布”动作自动化；最终发布永久禁止。
7. 所有写动作发生在真实可见 UI。Reader/目录/模板接口只读，保存回包只作证据。
8. 每件商品串行完成全部阶段和证据后，Runner 才能推进下一件。

## 2. 方案作用域与类目目录

### 2.1 账号、店铺和会话

- 店铺必须来自本次可见登录会话的 `shopMap`，并绑定账号/session generation 和 reason code。
- 草稿、类目、模板、方案、Schema、preview、snapshot 和审批都必须带 `shop_id` 与账号上下文。
- 切换账号、会话或店铺后，旧选品、类目、模板、确认输入和 preview 全部失效。
- 请求日志只记录 endpoint、scope、状态、耗时、条目数和 source hash；不记录 Cookie、请求/回包正文或业务样例。

### 2.2 动态目标叶子

类目选择必须消费 [category catalog manifest](../../resources/dxm/category-catalog/category-catalog.manifest.json) 和 [规范化 catalog](../../resources/dxm/category-catalog/category-catalog.v1.json)。校验命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\sync-dxm-category-catalog.ps1 -Check
```

方案目标类目必须：

- 支持任意树深度，不能固定三级；
- 只能选择 `executableLeaf=true` 的叶子；
- 以 `categoryId + nodeIdentitySha256 + catalog_hash` 为目录身份；
- 保存完整祖先 `nodePathIds[]` 和中英文路径用于审阅；
- 拒绝父链冲突、重复/歧义路径、缺祖先、非叶子或隔离节点；
- 搜索选择后按 ID 重新水合节点和完整祖先链。

类目 catalog 是方案选择和漂移检测参考，不是写动作时的最终真相。每件商品必须分别保存：

```text
source_category
  categoryId
  nodeIdentitySha256

target_category
  categoryId
  nodeIdentitySha256
  catalog_hash
  schema_hash
  capabilities_hash
```

来源与目标不一致时，preview 必须明确显示。正式页面切换后、任何字段写入前，必须从当前可见会话重读页面 `categoryId`、Schema 和能力并与冻结值精确比较。

## 3. 本地方案与店小秘引用分离

### 3.1 `local_plan_template`

本产品持有的版本化完整编辑规则，至少包括：

- 账号/店铺和目标叶子约束；
- 类目 catalog/schema/capability 身份；
- 固定值、补差规则、继承策略；
- 对店小秘模板引用的选择；
- 视频生成/选择/放置配置；
- 批发起订量、折扣和价格/库存约束；
- 翻译模式、方向、允许修改的自然语言字段；
- 半托管国家、货品、变种和物流配置；
- rollback preimage、恢复点和 UNKNOWN 策略；
- 两次保存与中间动作的证据策略。

### 3.2 `dxm_template_ref`

店小秘模板的只读引用身份，至少包括稳定类型/id、店铺、类目、显示名、同步时间、来源 endpoint、source hash、规范化值和 drift 状态。

两者不能共享模糊的 `template` 对象。模板漂移只影响新 preview；已经冻结的 snapshot 不得被静默改写。

### 3.3 冻结解析优先级

```text
明确固定值 fixed
  → 明确补差规则 fill
  → 已批准 dxm_template_ref 值
  → 当前商品值 current
  → unresolved（fail-closed）
```

“模板优先”指方案初始化和默认继承优先参考模板，不表示模板可以覆盖人工固定/补差。必填差集、条件依赖、类型、语言、价格和能力条件必须在 freeze 前全部闭合。

## 4. 动态中文编辑器与主编辑区

前端不维护固定字段数组，不让运营手写 JSON。后端根据当前店铺、目标叶子 Schema、模板引用和控件合同生成中文结构化模型。每个字段至少包含：

- `field_key`、Schema path、类型、required、条件依赖；
- `ui_label_zh`，仅供显示；
- 枚举、子属性、自然语言和预期语言；
- 稳定 `ui_binding` 与控件类型；
- current/template/fixed/fill 值与来源；
- 版本、source hash 和逐字段证据策略。

执行主键只能是冻结字段身份、Schema path 和稳定 binding。中文标签、`rc_select_N`、隐藏控件或运行期顺序不能单独定位写入。

产品把 DXM 原生 11 个 form 投影为 10 个运营区：基本、店小秘、属性、产品、区域调价、描述、包装、模板、合规和其它；模板主/税率在产品层合并。半托管是独立第二页面，不是第 11 个运营区。

## 5. 每件商品无条件必经的冻结阶段

方案 UI 必须显示以下阶段为“必需”，不能提供关闭开关：

### 5.1 VideoContract

- 冻结视频来源、生成/选择模式、目标位置、配额事实、请求/轮询政策和最终 readback。
- 执行前验证当前页面存在唯一可见控件、能力支持且配额语义明确。
- 视频生成如消耗额度或触发外部请求，视为独立 mutation，必须有 JIT、ledger 和 UNKNOWN。
- 最终证据至少包含 before 状态、request/action identity、videoId 或稳定结果身份、页面放置 readback。
- 缺能力、配额、稳定控件或证据时在首写前阻断整件商品。

### 5.2 WholesaleContract

- 冻结起订量、折扣阶梯、扣减/库存策略和适用 SKU。
- 校验 SKU 售价、货值、库存、批发价和折扣之间的明确关系；不能复用未经上游证明的全局公式。
- 按真实 Schema 和控件写入，逐项精确 readback；不得把配置回显当页面证据。
- 类目/店铺不支持、wire 语义不明或控件缺失时在首写前阻断。

### 5.3 TranslationContract

- 翻译必须在模板、固定值、补差、标题/描述生成全部完成之后执行。
- 只允许修改 Schema 标记的自然语言字段，例如标题、自由文本属性、PC/移动描述；禁止修改 id、枚举、URL、SKU 结构、数值和不可翻译专名。
- 冻结模式、方向、作用字段、before/expected、完成判据和语言策略。
- 保存前逐字段验证精确值、非空、Schema 和英文自然语言；`UNKNOWN`、混合语言、零变化或意外字段变化均阻断。

### 5.4 SemiManagedContract

- 每件商品必须进入 Path B：主编辑页启用半托管、第一次保存、处理中间 Modal、进入 `editFromSmt`、填写第二页并第二次保存。
- 国家、货品、变种和物流必须来自当前会话/页面真实选项并冻结稳定身份；禁止硬编码、默认全选或猜值。
- 含“继续发布”的按钮只有在命令分类为 `CONTINUE_TO_SEMI_MANAGED_EDITOR` 时允许自动化：必须验证精确 Modal、task/job/item、当前页面、预期请求、目标 URL、JIT/lease 和 ledger。
- 该动作只能进入半托管编辑页；任何最终发布、立即发布、保存并移入待发布或 online/release 意图永久拒绝。

### 5.5 RollbackSafetyContract

- 每件商品在首个页面写入前持久化逐字段/逐区域 preimage、页面/类目/Schema/session 身份和恢复顺序。
- 必须建立恢复点并验证恢复边界；这就是成功商品也必须执行的 rollback preparation。
- 首次保存派发前发生已知失败时，按逆序恢复并精确 readback；不能按正常顺序、仅改内存或只显示“已回滚”。
- 保存、视频或其它外部 mutation 已派发而结果不确定时，不得自动回滚、重试或补偿保存；必须 `UNKNOWN/needs_manual_review` 并停批。
- 保存后若未来需要补偿写，必须是另一份显式人工批准的任务，不属于自动 rollback。

## 6. Preview、freeze 与执行 payload

preview 必须逐商品展示：

- 当前账号/店铺/会话和 draft 身份；
- source/target category、动态路径、catalog/node/schema/capability hash；
- current/template/fixed/fill 来源与最终 resolution；
- 必填差集、条件依赖、类型、语言、价格和控件错误；
- 视频、翻译、批发、半托管和 rollback preparation 五项合同及真实支持状态；
- 两次保存、中间动作、三铁证和 UNKNOWN 策略；
- 所有不可执行审计项。

任一必经能力不完整时，preview 可以返回错误供运营修正，但不得冻结可执行任务。

freeze 必须原子建立 snapshot/task 幂等关系，并包含 ordered `item_snapshots[]`。最低逐商品结构：

```yaml
item_snapshot:
  product_identity: {}
  session_account_shop: {}
  source_category: {}
  target_category:
    categoryId: "..."
    node_identity_sha256: "..."
    catalog_sha256: "..."
    schema_sha256: "..."
    capabilities_sha256: "..."
  template_refs: []
  resolution_result: {}
  ui_bindings: {}
  required_capabilities:
    video: required
    translation: required
    wholesale: required
    semi_managed: required
    rollback_preparation: required
  video_contract: {}
  translation_contract: {}
  wholesale_contract: {}
  semi_managed_contract: {}
  rollback_contract: {}
  stage_a_save_contract: {}
  continue_to_semi_managed_contract: {}
  stage_b_save_contract: {}
  evidence_policy: two_stage_three_proofs
```

Runner 只能消费冻结 `resolution_result` 和上述合同，不得执行时重读“最新方案/模板”改变值，也不得删除必经能力后以兼容 Path A 继续。

## 7. 串行完整执行顺序

```text
当前队列 CAS + task/job/lease/JIT
  → 打开并核验真实主编辑页
  → 如需切类目：切换到冻结目标叶子并重读 Schema/能力
  → 全阶段零写预检
  → 持久化 rollback preimage 与恢复点
  → 填写主编辑页 10 个运营区 / 11 个原生 form
  → 视频阶段
  → 批发阶段
  → 翻译阶段
  → 主编辑页全字段精确 readback
  → 启用半托管
  → 第一次动作时 JIT/lease/ledger
  → 主编辑页精确“保存”
  → 第一阶段回包 + 页面状态 + 独立未发布证明
  → 精确中间“继续发布”动作
  → 进入并核验 editFromSmt
  → 填写国家/货品/变种/物流
  → 半托管页全字段精确 readback
  → 第二次动作时 JIT/lease/ledger
  → 半托管页精确“保存”
  → 第二阶段回包 + 页面成功态 + 独立未发布证明
  → 生成 CanonicalSaveReceipt
  → 下一商品
```

任何阶段失败时：

- 首个保存前且确认没有外部 mutation：执行逆序恢复并核验；
- 保存/视频/其它 mutation 派发后结果不确定：`UNKNOWN`、停批、保留现场；
- 不支持必经能力：本商品首写前失败，不能跳过；
- 最终发布信号：立即拒绝并终止。

## 8. 双阶段证据与结果

每次保存都必须分别绑定 task、job、item、snapshot、queue、runtime、session、页面、command 和 action：

1. 预期业务回包成功；
2. 对应页面成功态；
3. 独立未发布证明；
4. mutation ledger 闭合；
5. 逐字段 expected/readback 与冻结 payload 精确对应。

中间进入半托管页的动作还必须证明目标 URL/页面为 `editFromSmt`，没有最终发布。第一阶段证据不能复用为第二阶段证据；任一次三缺一都不能把商品标成成功。

结果页和 HVD 必须从同一持久事实投影完整阶段、两次保存、rollback/UNKNOWN 和剩余队列，不能由前端计时器或预制步骤推进。

## 9. 当前实现阻断与成熟度

| 必需能力 | 当前代码事实 | 关闭条件 |
|---|---|---|
| 动态类目 catalog | 源码态 catalog/manifest 已建立；执行消费和 portable 打包未证明 | 任意深度 UI、冲突隔离、snapshot/hash、写前实时复核、package smoke |
| 视频 | 类、状态和聚焦测试存在，多处页面动作/配额/证据未闭合 | 正式 Adapter、JIT/ledger、真实 request/poll/readback、负向和真机证据 |
| 翻译 | 入口/类存在，真实模式、作用域、完成判据和页面 readback 未闭合 | 正式 UI/Schema/Adapter、正常/对抗语料、逐字段证据 |
| 批发 | 配置和类存在，真实控件与价格/库存关系未闭合 | 真实 Schema/binding、全量预检、填写/readback、类目覆盖 |
| 半托管 | Legacy 有部分页面实现；正式 `batch_draft_save` 仍排除 Path B | 双阶段 snapshot/command/JIT/ledger/ActionResult、正式 worker 集成和真机证据 |
| rollback preparation | 当前 manager 偏内存/浅实现，未形成持久逐字段恢复合同 | 持久 preimage、逆序恢复、精确 readback、崩溃/UNKNOWN 测试 |
| Canonical receipt | Path A 合同已有片段，双阶段事实尚未统一 | 两次保存、继续动作、字段证据、未发布和运行身份统一持久化 |

这些是产品发布阻断，不是可删除的扩展。只有 UI → API → snapshot → execution payload →正式 Adapter → readback → ledger → receipt → 真机证据全部贯通后，才能关闭相应阻断。

## 10. 验收门禁

配置层至少证明：

- 当前账号/店铺隔离；
- 动态任意深度叶子目录、冲突隔离和 catalog/node/schema/capability hash；
- 模板身份、fixed/fill/template/current 解析、必填差集和条件依赖；
- 五项必经能力无法关闭、无法 skip、缺支持时首写前 fail-closed；
- snapshot/version/hash 不可变。

执行层至少证明：

- 正式 DxmWorkflowAdapter 和共享 binding registry；
- 每件商品依序执行视频、批发、翻译、半托管和 rollback preparation；
- 全阶段零写预检、逐字段 readback、动作时 JIT/lease/ledger；
- 精确中间“继续发布”只进入半托管页；
- 双保存各自三铁证、最终零发布、UNKNOWN 停批；
- 至少三件真实 draft 在同一任务中完整闭环。

交付层还要证明当前 Git/worktree/runtime/package 同源、完整 L0、0.3.0 portable 携带 catalog、启动/重启/恢复和诊断包安全。

任一层缺失都不能由另一层绿测替代。本文定义产品必须完成什么，不构成当前 READY 声明。
