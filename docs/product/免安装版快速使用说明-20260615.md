# DXM Agent Console 免安装版快速使用说明

更新时间：2026-07-22

## 适用范围

免安装版用于处理店小秘商品箱中的现有商品：

- 单商品只保存；
- 受控整批编辑保存；
- 查看真实浏览器、执行进度、保存证据和问题。

当前版本没有认领入口，也不会从其他列表创建或搬运商品。旧 `batch_save`、无人值守和发布功能不可用。

## 使用哪个 EXE

只使用从当前合并后 Git HEAD 新构建并完成 smoke 的 portable。旧 EXE 不包含当前功能删除结果，必须从交付目录移除，不能与新包混放。

默认构建产物：

```text
outputs\desktop-build\DXM-Agent-Console-Portable-0.1.0.exe
```

正式交付时应复制到一个全新的空目录，并同时提供 SHA-256 与构建 Git HEAD。目录版 `win-unpacked` 必须保留整个目录，不能只复制其中的 exe。

## 启动

1. 双击 portable。
2. 首次启动会解包 Electron 和 Python 运行时，`%TEMP%` 所在磁盘建议保留至少 1 GB。
3. 等待 Agent Console 主窗口出现，不需要手工启动后端或前端。
4. 若启动后立即退出，查看：

```text
%APPDATA%\DXM Agent Console\data\desktop-main.log
%APPDATA%\DXM Agent Console\data\backend.log
```

## 推荐操作顺序

1. 在“店小秘登录”打开真实登录页并完成登录/验证码。
2. 在“模板中心”确认店铺、类目、SKU、图片、物流、合规、半托管和引用模板。
3. 进入“商品箱编辑保存”，选择商品箱中的现有商品。
4. 单商品场景：创建 `single_save`，核对冻结的商品/店铺/来源，填写批准人并申请启动。
5. 整批场景：冻结当前可见商品范围和顺序，一次批准后由系统严格串行执行。
6. 在“真实浏览器”观察当前页面、HUD、日志和阻断原因。
7. 在“结果与问题”核对每个商品的保存回包、保存截图和独立未发布证明。

## 关键边界

- 只保存，不发布。
- 商品必须已经存在于商品箱，并具有可验证的店铺、来源和证据。
- L2 只读检查通过不等于保存授权；仍需服务端人工批准。
- 单次保存 READY 不代表整批 READY。
- 整批遇到 `UNKNOWN` 或已派发结果不确定时立即停止，不能自动重试。
- 任何身份漂移、批准过期、页面不匹配或发布信号都会阻断。

## 交付验收

新包必须来自干净 Git HEAD，并通过：

```bat
scripts\final-delivery-check.bat -RequireCleanWorktree -CheckPortableDesktop -ExpectedRealDxmWriteReadiness BLOCKED -ExpectedRealDxmSingleSaveEndToEnd pending_live_dxm_validation
```

完成同 HEAD 商品箱 L2 与真实单次保存现场证据后，才可以把两个期望值改为 `READY` 和 `passed`。

验收报告不能只看 `ok`；还要读取：

- `realDxmMutationScope`
- `realDxmWriteReadiness`
- `singleSaveAcceptance`
- `stateConsistency`
- Git/build/package identity
- portable SHA-256 与证据路径

## 登录异常

- 验证码必须在可见店小秘窗口中由用户完成。
- 不要并行启动多个 portable 或多个可见登录会话。
- 登录状态与任务页面不一致时，先停止任务并重新登录，不要绕过门禁。
- 若浏览器或进程异常退出，先查看日志和结果页；涉及保存派发不确定性时按人工对账处理。
