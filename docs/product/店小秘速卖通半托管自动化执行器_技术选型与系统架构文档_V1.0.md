# 店小秘速卖通半托管自动化执行器：技术选型与系统架构文档 V1.0

> 文档定位：给产品、开发、测试、自动化执行器适配使用。  
> 适用范围：店小秘速卖通采集箱、普通商品编辑页、半托管编辑页、保存到待发布。  
> 核心边界：默认只保存，不发布；配置驱动，状态机执行；失败进入异常池。  
> 依据：真实浏览器跑通流程与《店小秘速卖通半托管自动化操作流程（参考版）》。

---

## 1. 核心结论

本系统不应做成“AI 临场操作员”，也不应做成一次性脚本。正确方向是：

```text
字段先建模
模板先配置
页面按状态机执行
每步可校验
失败可追溯
发布强隔离
保存可闭环
```

V1.0 目标是完成一条稳定的半托管保存闭环：

```text
登录态检查
→ 进入速卖通采集箱
→ 定位目标商品
→ 写入领取标记
→ 打开普通编辑页
→ 填写普通商品信息
→ 勾选半托管参与
→ 进入半托管编辑页
→ 填写半托管信息
→ 只保存
→ 校验保存成功
→ 生成报告
```

V1.0 不做自动发布、不做全托管正式执行、不做多平台并发、不做云端代登录、不伪造合规资质。

## 2. 技术选型总览

| 层级 | 推荐选型 | 结论 |
|---|---|---|
| 桌面端 | Electron | V1.0 推荐 |
| 前端 | React + Vite + TypeScript | V1.0 推荐 |
| UI 组件 | Ant Design | V1.0 推荐 |
| 本地后端 | Python + FastAPI | V1.0 推荐 |
| 自动化执行器 | Playwright Python | V1.0 推荐 |
| 数据库 | SQLite | V1.0 推荐 |
| 状态机 | Python 自研状态机 | V1.0 推荐 |
| 实时通信 | WebSocket | V1.0 推荐 |
| 页面适配 | YAML / JSON Selector Profile | V1.0 推荐 |
| 证据存储 | Screenshot + DOM + Network Log | V1.0 推荐 |
| AI 能力 | 配置辅助 + 异常分析 | 非执行闭环 |

最终技术路线：

```text
Electron Desktop
  → React/Vite 控制台
  → FastAPI 本地后端
  → Python 状态机
  → Playwright 执行器
  → 真实店小秘浏览器页面
  → SQLite + 本地证据目录
```

## 3. 技术选型对比

### 3.1 桌面端：Electron vs Tauri

| 方案 | 优点 | 结论 |
|---|---|---|
| Electron | 与 React/Vite 集成简单，生态成熟，适合内嵌本地服务 | 推荐 |
| Tauri | 体积小，性能好 | 暂不推荐 |

V1.0 选择 Electron 的原因：

- 当前项目已经有 Electron 桌面壳方向。
- 与 React/Vite 组合成熟。
- 适合管理本地后端进程、截图、日志、SQLite、用户配置。
- Windows 运营电脑兼容性更直接。
- 对本地自动化工具而言，稳定性优先于安装包体积。

Tauri 可以作为 V2.0 轻量化方向，但不建议在 MVP 阶段切换底座。

### 3.2 后端：Python FastAPI vs Node.js

| 方案 | 优点 | 结论 |
|---|---|---|
| Python + FastAPI | 与 Playwright Python、状态机、日志处理、AI 分析更容易整合 | 推荐 |
| Node.js | 前后端同语言，Playwright 原生生态好 | 可选但不推荐 |

选择 Python FastAPI 的原因：

- 执行器、状态机、证据采集、异常归因可以在同一语言栈完成。
- FastAPI 适合本地 REST API 和 WebSocket。
- Python 更方便后续接入 AI 配置建议、异常总结、字段映射辅助。
- 本地单机版不需要复杂微服务。

### 3.3 自动化执行器：Playwright vs Selenium vs Browser-Use

| 方案 | 优点 | 结论 |
|---|---|---|
| Playwright | DOM、网络监听、截图、Trace、持久化会话能力强 | 推荐 |
| Selenium | 成熟但现代前端页面适配效率较低 | 不推荐 |
| Browser-Use | 适合探索型 AI 浏览器代理 | 不作为主执行器 |

V1.0 使用 Playwright Python。Browser-Use 或 AI Agent 不进入正式执行闭环，只能作为探测或辅助分析工具。

核心原因：

- 店小秘页面字段复杂，必须确定性执行。
- 发布风险不能靠 AI 猜。
- 商品归属锁、发布隔离、字段真实性需要程序硬约束。
- 批量任务需要可复盘、可重试、可验收。

### 3.4 数据库：SQLite vs PostgreSQL

| 方案 | 优点 | 结论 |
|---|---|---|
| SQLite | 本地单机简单稳定，无部署成本 | 推荐 |
| PostgreSQL | 适合团队版、云端、多用户 | 后置 |

V1.0 是本地桌面版，SQLite 足够支撑任务、配置、异常、证据索引和报告。

后续如果做多人协作、云端任务、团队审批，再迁移 PostgreSQL。

### 3.5 任务调度：单进程队列 vs Celery

| 方案 | 优点 | 结论 |
|---|---|---|
| 单进程任务队列 | 简单、可控、适合本地串行自动化 | 推荐 |
| Celery | 分布式任务能力强 | 暂不推荐 |

V1.0 不需要 Celery。店小秘自动化早期应单任务、单浏览器、单商品串行执行，避免多标签、多上下文造成误操作。

## 5. 执行模式设计

### 5.1 推荐的 5 种执行模式

| 模式 | 是否改数据 | 用途 |
|---|---|---|
| probe | 否 | 页面探测、登录态检查、选择器验证 |
| dry_run | 否 | 任务预检、字段完整性检查 |
| claim_only | 是，仅备注 | 领取锁定目标商品 |
| single_save | 是 | 单商品完整保存验证 |
| batch_save | 是 | 小批量保存到待发布 |

### 5.2 V1.0 默认开放模式

V1.0 建议默认开放：

```text
probe
 dry_run
 claim_only
 single_save
```

V1.0 后期再开放：

```text
batch_save
```

### 5.3 永久禁止模式

```text
publish
continue_publish
save_and_publish
```

发布相关动作必须在执行器层、配置层、前端层三层禁止。

### 5.4 执行模式说明

#### probe：探测模式

不修改任何数据。用于检查登录态、菜单路径、采集箱 URL、弹窗遮挡、页面结构、选择器有效性。

输出：

```text
页面 URL
页面标题
主要 DOM 节点
可见按钮
截图
选择器检测结果
```

#### dry_run：预检模式

不修改任何数据。用于检查任务是否能安全执行。

检查项：

- 店铺是否唯一。
- 商品筛选是否唯一。
- 类目模板是否完整。
- SKU 规则是否完整。
- 图片规则是否完整。
- 半托管模板是否完整。
- 是否存在发布风险。

#### claim_only：领取锁定模式

只给目标商品写入领取备注，例如 `AI认领`。这是后续编辑的安全前置。

成功信号：

```text
商品行出现备注:AI认领
```

#### single_save：单品保存模式

完整跑通一条商品。适合新类目、新店铺、新页面首次验证。

建议暂停点：

```text
打开编辑页后
普通信息填完后
进入半托管页后
保存前
```

#### batch_save：批量保存模式

多个商品串行执行。每条商品独立执行状态机，失败进入异常池，成功生成报告。

默认并发：

```text
concurrency = 1
```

```text

→ CAPTURE_EVIDENCE
→ WRITE_EXCEPTION

```

### 6.3 状态节点规范

每个状态节点必须具备：

```text

action
expected_url
expected_text

retry_policy

```

## 8. 页面定位策略

### 8.1 定位优先级

执行器按以下优先级定位页面元素：

1. URL 与页面标题。
2. 语义文本。
3. 表单 label。
4. 表格表头与行列关系。
5. DOM class 与组件结构。
6. 元素 bounding box。
7. 截图识别。

坐标不能作为主策略。坐标只能来自 DOM 元素的 bounding box，并作为最后兜底。

### 8.2 变种表格定位

变种表格必须使用：

```text
表头列名 + 行变种名
```

示例：

```text
行：白色(Stand 1)
列：SKU编码
值：DXM104957400423001
```

禁止直接用“第几个 input”。页面新增列、滚动位置变化、列折叠都会导致错填。

### 8.3 页面适配配置示例

```yaml
pages:
  smt_draft_list:
    url_contains: "/web/smt/smtProductList/draft"
    row_match:
      - title
      - store
      - remark

  smt_edit:
    title_label: "产品标题"
    save_button_text: "保存"
    semi_button_text: "编辑半托管信息"
    forbidden_buttons:
      - "立即发布"
      - "发布"
      - "继续发布"

  smt_semi_edit:
    url_contains: "editFromSmt"
    save_button_text: "保存"
    forbidden_buttons:
      - "立即发布"
      - "发布"
```

## 9. 发布隔离架构

### 9.1 三层发布隔离

```text
配置层：execution_mode = save_only, publish_allowed = false
前端层：不提供发布按钮，不提供发布任务模式
执行器层：forbidden_buttons + 弹窗检测 + 保存前复核
```

### 9.2 禁止按钮

默认禁止：

```text
立即发布
发布
继续发布
保存并发布
确认发布
提交发布
```

如果页面出现发布确认或风险确认，执行器必须停止并写入异常池。

### 9.3 保存前检查

点击保存前必须检查：

```text
当前商品仍属于当前任务
当前页面不是发布确认页
立即发布按钮未被选中
未出现发布确认弹窗
目标按钮文本为保存
```

## 10. 商品归属锁架构

### 10.1 归属条件

商品必须满足至少一项：

```text
来自当前任务队列
商品行已有当前任务领取标记
详情页店铺、标题、SKU 或商品 ID 与任务 payload 一致
```

### 10.2 推荐锁定字段

```text
task_id
store_name
product_id
source_title
claim_mark
claim_color
sku_prefix
created_at
```

### 10.3 锁定流程

```text
定位商品行
→ 写入 AI认领
→ 回读备注
→ 记录 product_id / title / store
→ 打开编辑页
→ 再次校验归属
→ 允许编辑
```

如果任一环节不一致，立即停止。

## 14. 异常池设计

### 14.1 异常分类

| 错误码 | 类型 | 处理策略 |
|---|---|---|
| E101 | 登录失效 | 人工登录后重试 |
| E102 | 弹窗遮挡 | 自动关闭或人工接管 |
| E201 | 商品定位失败 | 检查筛选条件 |
| E202 | 商品归属异常 | 停止，防止误操作 |
| E301 | 类目异常 | 修正类目模板 |
| E302 | 属性缺失 | 补齐模板 |
| E401 | 图片异常 | 检查图片配置 |
| E501 | SKU 异常 | 修正 SKU 规则 |
| E502 | 价格异常 | 修正计价配置 |
| E601 | 物流异常 | 修正物流模板 |
| E701 | 合规异常 | 补齐合规模板 |
| E801 | 半托管校验失败 | 按页面提示补齐 |
| E802 | 半托管保存失败 | 记录接口返回 |
| E901 | 页面结构变化 | 更新页面适配配置 |
| E999 | 发布风险 | 立即停止 |

### 14.2 异常处理动作

允许：

```text
查看证据
修改配置
重新执行当前商品
跳过商品
标记已处理
```

禁止：

```text
强制发布
忽略商品归属异常继续执行
忽略合规缺失继续执行
忽略发布确认继续执行
```

## 15. AI 能力边界

### 15.1 AI 可以做

```text
生成标题模板建议
生成类目字段映射建议
分析失败日志
总结异常原因
生成配置草案
辅助写测试用例
```

### 15.2 AI 不可以做

```text
临场决定选哪个类目
临场决定填哪个品牌
临场伪造条码或资质
决定是否继续发布
忽略页面错误
绕过验证码
```

AI 是配置助手与异常分析助手，不是浏览器执行员。正式运行必须由确定性状态机执行。

## 19. 风险与控制

| 风险 | 影响 | 控制方式 |
|---|---|---|
| 页面结构变化 | 选择器失效 | Selector Profile 热更新 |
| 弹窗遮挡 | 操作失败 | ModalAdapter 自动处理 |
| 登录失效 | 执行中断 | 人工接管 |
| 商品误匹配 | 数据被误改 | 商品归属锁 |
| 发布误触 | 商品上架风险 | 发布强隔离 |
| 图片银行失败 | 字段无法补齐 | 图片备用来源 |
| SKU 重复 | 保存失败 | SKU 规则校验 |
| 合规缺失 | 平台校验失败 | 合规模板必填 |
| 半托管保存失败 | 任务失败 | 网络返回解析 |

## 20. V1.0 最终推荐

V1.0 应采用：

```text
Electron + React + Vite + TypeScript
Python + FastAPI + SQLite
Playwright Python
自研状态机
YAML/JSON 页面适配配置
WebSocket 实时事件
本地截图 / DOM / 网络日志证据
AI 只做配置辅助和异常分析
```

V1.0 默认执行：

```text
probe → dry_run → claim_only → single_save
```

V1.0 后期开放：

```text
batch_save
```

V1.0 禁止：

```text
publish
continue_publish
save_and_publish
```

最终方向：

```text
本地运行
配置驱动
状态机执行
单线程强校验
商品归属锁
发布强隔离
证据可追溯
保存到待发布
```

这套架构可以先稳定跑通半托管保存闭环，再逐步扩展到全托管、多类目、多店铺和批量断点续跑。
