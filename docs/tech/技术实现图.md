# 店小秘自动刊登助手 技术实现图文档

> **历史设计（v0.1）。** 本文是早期产品蓝图，不描述 2026-07-17 的持久化 Browser Agent、两段式验收、状态一致性或 mutation ledger。当前架构见 [当前运行时架构](当前运行时架构-20260717.md)。

> 版本：v0.1
> 目标：为“本地客户端 + 可视化执行 + 操控店小秘完成自动刊登”的产品提供技术蓝图。

## 1. 产品目标

本产品不是 ERP，也不是单纯采集器。

它的定位是：

1. 让卖家继续使用店小秘
2. 让卖家在本地客户端中可视化完成任务配置
3. 让程序自动操控店小秘完成创建商品、保存待发布、发布等操作
4. 全过程对用户可见，必要时支持人工接管
5. 默认敏感数据仅保存在本机

## 3. 架构设计原则

### 3.1 本地优先

敏感数据默认不出本机：
- 店小秘登录态
- 商品任务原始数据
- 操作截图与日志
- 本地配置规则

### 3.2 可视优先

程序不是黑盒脚本。
用户必须能看到：
- 当前正在做什么
- 当前正在操作哪一步
- 页面是否真的进入目标位置
- 异常发生在哪里

### 3.3 可接管

当出现验证码、类目判断异常、页面结构变化时：
- 程序暂停
- 用户接管
- 用户处理后交还程序继续执行

### 3.4 适配层隔离

平台自动化逻辑必须通过 Adapter 进行隔离。
这样以后扩展 Shopee/Lazada/eBay 时，不需要重写任务引擎。

## 4. 核心模块说明

## 4.1 UI 操作台（HTML）

建议形态：
- Tauri 或 Electron 容器
- 内嵌前端页面（React/Vue）

功能：
- 展示仪表盘
- 导入商品
- 配置规则
- 启动任务
- 监控执行进度
- 查看异常池
- 查看日志与截图

输出：
- 向 Task Engine 发出命令
- 接收后台事件流实时刷新界面

---

## 4.2 任务编排引擎 Task Engine

作用：
- 接收 UI 发起的任务
- 将任务拆成多个 Job
- 控制执行顺序、暂停、继续、重试、终止
- 管理状态机
- 支持断点续跑

一个批次任务可能包含：
- 任务 Task：例如“6月速卖通铺货批次”
- 商品 Job：例如一个具体商品的执行单元
- 步骤 Step：例如“打开创建页”“填写标题”“上传图片”

### Task 状态

```text
draft
queued
running
paused
completed
failed
partial_success
cancelled
```

### Job 状态

```text
pending
preprocessing
waiting_login
waiting_manual_action
opening_page
filling_form
uploading_images
saving_draft
publishing
success
failed
retrying
blocked
```

---

## 4.3 商品处理引擎 Product Processor

作用：
- 将导入的商品变成标准化可发布数据

子模块建议：

1. 标题处理
- 标题清洗
- 禁词过滤
- 翻译
- 标题模板重组

2. 描述处理
- 生成卖点
- 生成简版描述
- 过滤非目标语言文本

3. 价格处理
- 读取成本
- 根据规则计算售价
- 支持用户自定义公式

4. 属性处理
- 源字段到速卖通字段的映射
- 默认值填充
- 缺失字段提示

5. 图片处理
- 图片完整性检查
- 主图数量检查
- 营销图规则提示
- 本地图片路径校验

### 输入
- Excel/CSV
- 商品链接
- 用户手工输入

### 输出
- 标准 product payload
- 校验结果
- 异常标记

## 4.4 店小秘适配层 Dxm Adapter

作用：
- 将“发布一个商品”的抽象指令转成店小秘网页操作步骤

建议方法接口：

```text
DxmAdapter.ensure_login()
DxmAdapter.select_store(store_id)
DxmAdapter.open_create_page(platform)
DxmAdapter.fill_basic_info(product)
DxmAdapter.fill_attributes(product)
DxmAdapter.fill_variants(product)
DxmAdapter.fill_images(product)
DxmAdapter.fill_pricing(product)
DxmAdapter.save_draft()
DxmAdapter.publish()
DxmAdapter.capture_error()
```

这一层不做复杂业务规则，只做页面动作映射。

## 4.5 浏览器执行器 Playwright Worker

作用：
- 实际控制店小秘网页

建议拆分：

### BrowserManager
- 启动浏览器
- 恢复浏览器上下文
- 管理持久化会话目录

### SessionManager
- 校验登录态是否失效
- 本地保存 cookie/session
- 清理过期会话

### PageNavigator
- 打开指定模块
- 导航到速卖通创建页
- 切换店铺/平台

### ActionExecutor
- 点击按钮
- 输入文本
- 选择下拉项
- 上传文件
- 等待成功提示

### EvidenceCollector
- 截图
- 保存 HTML 快照
- 捕捉控制台报错
- 收集网络异常信息

## 5. 关键交互流程图

## 5.1 登录流程

```text
[用户打开客户端]
      ↓
[登录产品账号]
      ↓
[主界面加载成功]
      ↓
[用户点击“连接店小秘”]
      ↓
[右侧打开真实店小秘登录页]
      ↓
[用户在店小秘页面输入账号密码]
      ↓
[Playwright 持久化会话]
      ↓
[本地保存 session/cookie]
      ↓
[UI 显示：店小秘已登录]
```

说明：
- 密码不通过你自己的表单收集
- 用户在真实店小秘页面输入账号密码
- 信任度最高

---

## 5.2 商品执行流程

```text
[用户导入商品]
      ↓
[UI 操作台]
      ↓
[Task Engine 创建 Task]
      ↓
[Product Processor 预处理]
      ↓
[校验 PASS ?]
   ├─是 → [加入执行队列]
   │         ↓
   │   [Dxm Adapter]
   │         ↓
   │   [Playwright 执行]
   │         ↓
   │   [店小秘页面]
   │         ↓
   │   [回写 success / failed]
   │
   └─否 → [异常池]
```

---

## 5.3 验证码与人工接管流程

```text
[程序执行中]
      ↓
[发现验证码/风控弹窗]
      ↓
[Job 状态切换为 waiting_manual_action]
      ↓
[UI 弹窗提示：请手工处理]
      ↓
[用户在右侧浏览器处理验证码]
      ↓
[用户点击“继续执行”]
      ↓
[Task Engine 从当前 Step 恢复]
```

由于店小秘页面会变化，不能把页面元素选择器完全写死在代码里。

建议配置格式：

```json
{
  "aliexpress.create.title_input": [
    "input[name='subject']",
    ".subject-editor input",
    "[placeholder='请输入产品标题']"
  ],
  "aliexpress.create.category_button": [
    ".category-selector button",
    "button.select-category"
  ],
  "aliexpress.create.save_button": [
    "button.save-draft",
    ".footer-actions .save-btn"
  ]
```

### 优点
- 页面变化后可热修复
- 不必每次都发新版客户端
- 云端可以下发兼容配置

## 8. 异常池设计

异常池不是“失败列表”，而是“可处理的待办列表”。

### 建议错误编码

```text
E100 登录失效
E101 验证码
E102 页面结构变化
E103 类目无法匹配
E104 属性缺失
E105 标题违规
E106 图片上传失败
E107 运费模板冲突
E108 发布接口返回失败
E109 页面卡死/超时
E110 网络异常
```

### 每条异常应展示
- 商品标题
- 任务名称
- 发生时间
- 错误分类
- 失败截图
- 原始报错
- 建议处理动作
- 一键重试入口

### 示例

```text
错误：E107 运费模板冲突
建议：检查发货地是否与模板匹配；或切换至 AE-CN-01 模板。
操作：[打开商品] [修复并重试] [忽略]
```

### 12.15 产品实现建议

前端上要单独做一个“模板中心”页面；
后端/本地数据库中要把这些模板与：
- store_id
- platform
- category_id
- template_type
绑定起来。

否则以后自动化跑起来后，会因为配置分散导致：
- 改一个模板要到处改
- 多店铺复用困难
- 新类目上线很慢
- 异常排查困难

## 13. 与 PRD 对齐的产品架构约束

为避免后续产品设计与技术实现脱节，架构层必须满足以下 PRD 约束：

### 13.1 以模板中心为数据入口，而不是以单商品编辑页为数据入口

也就是说，系统默认数据流应为：

```text
模板中心配置
→ 商品导入
→ 模板自动绑定
→ 差异字段补全
→ 执行器填充店小秘
```

而不是：

```text
每个商品逐个手填
→ 再由执行器照抄
```

### 13.2 发布场景必须内建分流

系统至少要区分：
- 跨境 POP
- 半托管
- 全托管（预留）
- 海外托管（预留）

不同场景对应不同的字段校验与执行步骤。

### 13.3 执行器必须支持“字段域驱动”

执行步骤不应只按页面写死，而应按字段域加载：
- 标题域
- 类目资质域
- 媒体素材域
- SKU价格域
- 包装物流域
- 合规责任主体域
- 半托管报价域

这样后续页面结构变化时，只需调整字段域与页面映射，而不是整体推翻执行器。

### 13.4 UI 必须区分“高频字段”和“高级字段”

高频字段：
- 标题
- 类目
- 主图
- SKU
- 价格
- 运费模板

高级字段：
- 欧盟负责人
- 制造商
- GPSR
- 资质 PDF
- 白底图 / 营销图 / 安装视频
- 半托管报价与履约参数

前台上应支持：
- 默认简版视图
- 高级字段展开视图
- 模板中心集中维护

### 13.5 异常池要与字段域强绑定

异常展示不能只写“发布失败”，必须知道失败属于哪个域：
- 标题域
- 类目资质域
- 图片视频域
- SKU价格域
- 合规域
- 半托管报价域

这样用户才能快速修复并重试。

## 14. 最终落地结论

这套技术架构最适合你的产品方向：

1. 不要求卖家迁移 ERP
2. 店小秘账号密码仍在真实店小秘页面输入
3. 敏感数据默认本地保存
4. 自动执行全过程可视化
5. 出异常时用户可立即接管
6. 后续易于扩展到多平台

### 一句话总结

这不是一个黑盒脚本，而是一套“本地运行、可视化、可接管、可追溯”的店小秘自动操作系统。
