## 正式包的使用原则

1. 双击 portable 后只保留一个 DXM Agent Console 实例。
2. 店小秘登录和真实操作发生在独立可见浏览器窗口；控制台负责方案、任务、HVD 和结果。
3. 账号密码如由桌面端记住，只能使用系统本机加密存储；不得写入方案、日志或文档。
4. 关闭程序前先确认没有运行中、暂停确认中、停止确认中或结果未知的真实任务。
5. 每件商品的完整成功必须经过视频、翻译、批发、Path B 半托管和 rollback preparation；任一项未执行或缺证据都不是成功。
6. 最终“发布”“立即发布”“保存并发布”“保存并移入待发布”永久禁止。Path B 的欧盟外包装确认中间 Modal 可在精确上下文核验后自动点击“继续发布”，但这不授权任何最终上线动作。

## 常见启动错误

### 已有实例使用同一数据目录

错误码：`DXM_SAME_DATA_RUNTIME`。

含义：旧窗口或旧后端仍持有同一 SQLite、浏览器会话和写入账本。请回到原窗口正常退出；不要让新窗口自动接管或杀进程。若原窗口已丢失，由维护人员核对错误页给出的 PID、进程路径和命令行，确认没有真实任务后再结束旧进程。

### 页面打开但服务没有加载

先保留错误页并查看：

```text
%APPDATA%\DXM Agent Console\data\desktop-main.log
%APPDATA%\DXM Agent Console\data\backend.log
```

不要把完整日志直接发送给外部人员；先导出脱敏诊断包。日志中若显示版本、build identity、数据目录或后端实例不一致，应停止使用该包。

## 验包人员

当前源码构建新包后，至少核对：

- 版本来自 `app/desktop/package.json`，文件名没有旧版本硬编码；
- build manifest、Git、工作树与 backend/frontend/desktop 版本同源；
- 使用隔离 user-data 启动、关闭、重启并读回状态；
- `DXM_SAME_DATA_RUNTIME` 反例不会误杀旧实例；
- frontend build、desktop tests、完整 backend 门禁和文档校验通过；
- 登录、Reader、动态任意深度类目目录、preview/freeze 可用；目录只负责发现和冻结，真实执行以当前可见页面 categoryId/Schema 为权威；
- 视频、翻译、批发、Path B 双保存和 rollback preparation 全部接入同一正式 Runner、BrowserAgent、读回与持久证据；
- 至少三件真实 draft 从同一 package 完成完整 Path B，两次保存分别有可复核事实，并有独立未发布证明；
- 精确中间“继续发布”反例不会放宽最终 PublishGuard；其它发布信号全部拒绝；
- 真实保存只在单独人工授权后执行，任一 `UNKNOWN` 停批且不自动重试。

当前 0.3.0 源码尚未满足上述完整产品门禁，因此即使能够启动、登录、Reader 或完成 Path A，也不能把 portable 标为可发布产品或 READY。
