### 2.3 `DXM_SAME_DATA_RUNTIME`

该错误表示另一个 DXM Agent Console 实例仍持有同一数据目录。它是保护数据库、会话和写入账本的互斥门禁，不应自动杀进程或接管。

处理顺序：

1. 回到原 DXM 窗口，确认没有 `running`、`pause_requested`、`stop_requested` 或待人工对账任务。
2. 从原窗口正常退出，等待后端进程结束。
3. 若原窗口已丢失，先按错误页给出的 PID 做只读核对：

```powershell
Get-CimInstance Win32_Process -Filter "ProcessId = <PID>" |
  Select-Object ProcessId, Name, ExecutablePath, CommandLine
```

4. 只有确认 PID 属于本项目旧实例、没有真实任务且已记录现场后，才显式结束该 PID：

```powershell
Stop-Process -Id <PID>
```

5. 重新打开一次。不要同时启动源码版、目录版和 portable 指向同一数据目录。

## 3. 当前 UI 主路径

七项导航固定为：工作台、连接店小秘、采集箱选品、铺货方案、开始批量保存、保存结果、设置。

### 3.1 连接店小秘

1. 打开“连接店小秘”。
2. 点击打开真实登录页；在独立可见浏览器中完成人工登录或验证码。
3. 返回控制台检测连接。
4. 只有状态为 `LOGIN_READER_READY`，且 reason code、账号和 Reader 同源时才继续。

`/web/home` 证明可见页面已登录，但 Reader 还要在同一会话用账号级 `userInfo` 建立证明。`BROWSER_SESSION_UNAVAILABLE`、`DXM_PAGE_REQUIRED`、`DXM_SESSION_BUSY` 或账号变化都必须阻断旧选品。

### 3.2 采集箱选品

UI 通过当前 backend：

```text
GET /api/dxm/draft-reader/shops
GET /api/dxm/draft-reader/products?...
```

操作：

1. 可先用“全部店铺”做只读浏览/筛选；勾选和确认任务输入前必须选择一个具体真实店铺。
2. 刷新分页列表，确认来源为真实 Reader，不是 fallback/mock。
3. 在同一具体店铺内选择至少 3 个 `dxmState=draft` 商品；切店后旧选择必须失效，禁止跨店 selection。
4. 确认商品身份、店铺、类目和会话均来自当次读回。

刷新失败、换账号、换会话、卸载页面或 Reader 失败后，旧 `productIds` 和确认输入必须失效。

### 3.3 铺货方案

1. 选择当前店铺和一个目标末级类目。类目选择器必须支持任意深度，并只接受 `isleaf=1`；不得把“第三级”推断成叶子。
2. 从版本化类目目录定位完整路径和叶子 ID，再点击读取当前会话的真实类目字段、模板和 capability。目录用于发现和冻结；执行时仍以当前可见页面的 categoryId/Schema 为权威。
3. 按中文 10 区审阅字段；这些是产品投影，DXM 原生页面观察为 11 form。
4. 配齐属性、运费、服务、产品、变种和尺码等模板；任何被当前商品或类目要求的值都不能留到运行时猜测。
5. 对每个字段选择继承、补差或固定；自然语言自动写入值必须英文。
6. 配置并审阅每件必经的视频、翻译、批发和 Path B 半托管策略。任一能力缺少真实控件、稳定 binding、合法值或预期读回时，方案必须判 `BLOCKED`，不能降级为跳过。
7. 配置 rollback preparation：在任何字段修改或外部 mutation 前要捕获哪些 preimage、如何逆序恢复、如何读回证明。实际 restore 只在失败路径触发。
8. 保存本地方案版本。当前 UI/Runner 尚未完整贯通上述 REQUIRED 能力，所以形成配置不等于允许真实执行。

## 4. 完整 Path B 真实验收（当前 BLOCKED）

当前状态不允许把下面步骤当普通用户操作。完整 L0 已于 2026-08-28 清零，但只有 [BLOCKED](../../BLOCKED.md) 中其余生产接线、固定源码/同源 package、真实页面负向测试和人工授权门禁全部关闭，才可由有权限人员执行：

1. 从同一 UI、同一可见会话创建新的三商品 snapshot/task；不得复用历史 task。
2. 记录 Git/worktree/build/package/runtime/data identity。
3. 对每件商品确认目标为目录中的真实叶子，并验证视频、翻译和批发的当前可观察能力；半托管资格不得预检，只能由稍后点击 `OPEN_SEMI_MANAGED_EDITOR` 后的店小秘原生门裁决。任一可在首写前确认的 REQUIRED 能力不支持就停止。
4. 用 `POST /api/tasks/{task_id}/approve-and-start` 做原子批准并开始；批准必须覆盖商品顺序、类目/Schema、五项 REQUIRED 能力、两段保存和证据合同。
5. Runner 串行处理。每件先复核当前页面商品、店铺、categoryId、Schema 和 capability；如需切类目，必须从可见 UI 切换后重新读取，目录缓存不能覆盖 live 漂移。
6. 在任何页面修改或外部 mutation 前持久化 preimage 和 rollback plan；预检所有稳定 binding、可见控件和目标值。
7. 填写主编辑字段，实际执行视频、SKU/批发和翻译；翻译位于所有自然语言生成完成之后。逐项精确读回，任何 REQUIRED 能力不得记为 skip。
8. 完成主编辑全字段预检后，为最早可能触发 SAVE1 的顶部精确“保存”建立 JIT/lease/ledger，并开启同一多步 FIRST_SAVE handshake；提示 Modal 本身不算保存成功。
9. 在同一 active handshake 下精确点击 `OPEN_SEMI_MANAGED_EDITOR`，只观察店小秘原生门 admitted/rejected/unknown；不得主动调用或重放资格接口。按真实 network/page/ledger 事件分别闭合 SAVE1 与门结果，不硬编码二者墙钟先后。
10. 只有 `SAVE1 verified + native gate admitted + same-handshake causal binding` 均成立后，才允许在已验证的特定 Modal 上点击精确“继续发布”（`SEMI_MANAGED_CONTINUE_TRANSITION`）；上下文不完整、门拒绝或任一事实不确定立即停止。
11. 在 `/web/smt/editFromSmt` 重新验证页面身份并完成第二页全量零写预检，再填写和读回参加国家、货品信息、变种价格/编码/JIT 库存等冻结值。
12. 执行第二次独立 JIT/lease/ledger，点击半托管页精确“保存”。当前商品的两段保存和完整未发布证明闭合前不推进下一件。
13. 在真实任务上验证暂停 ≥10 秒、继续不重做、停止不再派发。
14. 任一外部 mutation 派发不确定立即进入 `UNKNOWN`、停批并人工对账；禁止自动重试或声称已 rollback。

永久禁止：主编辑或半托管页的最终“发布”“立即发布”“保存并发布”“保存并移入待发布”及任何最终上线请求。允许的中间“继续发布”不是全局文字白名单，也不授权直接调用写接口。

## 5. 结果与证据

“保存结果”必须按 task → ordered job → product → action 展示：

- snapshot/hash、队列位置和运行身份；
- SAVE command、mutation ledger 与动作时间；
- 回包、页面成功态、独立未发布证明；
- 逐字段预期/读回；
- 视频、翻译、批发和 rollback preparation 的逐项 before/after 与读回；
- Path B 主编辑保存和半托管保存各自的 command、JIT/lease、ledger、业务回包与页面事实；
- `succeeded`、已知前置失败或 `UNKNOWN/needs_manual_review`；
- HVD、日志、API、SQLite 与报告的一致性。

没有五项 REQUIRED 能力证据、两段保存事实或完整三铁证的商品不得计入成功。旧报告、mock、HTML、手工截图或“未点发布”不能补齐证据。

## 7. 停止与现场保护

- 正常停止：关闭启动器/桌面窗口；有真实任务时先在 UI 安全停止并等待 worker ack。
- 视频生成、主编辑保存、半托管保存等外部 mutation 派发后进程异常：不要重启后自动重试，保留 ledger、日志和页面，状态应为 `UNKNOWN`。
- 首次外部 mutation 前失败：按冻结 rollback plan 逆序恢复页面并精确读回；恢复不完整同样停批。外部 mutation 已派发后不得用第二次写入冒充回滚。
- 不删除 `data/**`、SQLite、runtime lock、证据或日志来“解决”状态冲突。
- 不启动第二个同数据目录实例，不强占正在服务真实任务的 8000 端口。
- 不提交 Cookie、账号密码、token、raw 抓包、真实业务样例或诊断原文。
