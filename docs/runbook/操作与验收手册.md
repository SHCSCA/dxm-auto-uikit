### 2.3 `DXM_SAME_DATA_RUNTIME`

该错误表示另一个 DXM Agent Console 实例仍持有同一数据目录。它是保护数据库、会话和写入账本的互斥门禁，不应自动杀进程或接管。

处理顺序：

1. 回到原 DXM 窗口，确认没有 `running`、`pause_requested`、`stop_requested` 或待人工对账任务。
2. 从原窗口正常退出，等待后端进程结束。
3. 若原窗口已丢失，先按错误页给出的 PID 做只读核对：

```powershell
Get-CimInstance Win32_Process -Filter "ProcessId = <PID>" |
  Select-Object ProcessId, Name, ExecutablePath, CommandLine
```

4. 只有确认 PID 属于本项目旧实例、没有真实任务且已记录现场后，才显式结束该 PID：

```powershell
Stop-Process -Id <PID>
```

5. 重新打开一次。不要同时启动源码版、目录版和 portable 指向同一数据目录。

### 4.1 外部 scope、ApprovalFile 与一次性阶段驱动

真实写 scope 和 ApprovalFile 必须位于 Git 工作树之外。不要把真实店铺、商品、字段值、账号、会话、nonce 或审批原文写入仓库、命令历史、报告或截图说明。scope 只保存受控身份与 hash，并必须满足 [JSON Schema](../../config/real_dxm_write_scope.schema.json)：

当前公开前端组件的翻译语言行会直接执行翻译；视频进度结束后的投放按钮不能单独证明业务成功。系统只读检查新增私有 `contentSurface` 记录这些实际控件形状，始终不确认翻译、不生成或投放视频，不签发 capability。静态组件事实及合成 DOM 检查不代替新运行时的现场观察；正式动作仍必须消费同一共享模板，并在不确定结果后停止派发。

翻译新增生产接线使用原生语言行和统一授权派发：逐个实际请求核对当前共享输入、普通中译英和业务成功，随后核对实际服务输出与完整字段读回，SKU 身份/价格/结构不得变化。原生 click 返回只确认派发，不代表业务成功；服务失败后的切换、延迟重试或结果不确定不能当作继续执行的依据。翻译现已接入原 Worker 文件、批发前序、实际 ledger/冻结权威及截图的持久绑定，Runner 拒绝来源缺失或重复回执；来源持久验证失败归 UNKNOWN 并停止。这些代码仅完成局部检查，最终完整输出冻结及 SAVE1 消费仍未完成，视频/半托管也未现场闭环；不得手动执行该方法绕过唯一系统流程脚本或据此释放 capability。

真实操作规则以 [运营操作详细文档 §4、§6–§9](运营操作详细文档.md#4-主编辑页--11-分区逐区操作) 和 [统一方案 §6.4](../architecture/DXM-工作台与分区自动化统一开发方案.md#64-contentfinalize-与-11-区-readback-协调v110-新增) 为依据。逐商品顺序为：原值及恢复准备 → 主编辑 11 分区填写/读回 → 视频生成或选择并投放 → 批发关系验证 → 翻译 → 全字段核对 → SAVE1/原生半托管入口 → S1–S3 填写/读回 → SAVE2。批发填写属于产品信息分区，之后独立复核；不能为方便接线改变顺序或跳过必经阶段。

必须区分运营规则、配置值与页面事实：运营文档的“前 6 张”是产品图片选取规则，不直接决定视频源图；数字示例、历史候选流程及公开组件默认转场/音乐均不是本次共享方案值。已配置项不重复询问；缺项先核对现有共同规则和引用，仍无法确定才询问用户，并通过唯一 Configure 流程写回共享模板，禁止商品例外。2026-09-08 公共 API 读回 v1.4.0 仍为 draft：视频有启用/等待/失败策略但无源图、转场、音乐规则；半托管 source_snapshot 已有全选实际可用国家的意图，空 countries 不等于用户未选择策略，实际集合须在原生门后按共同规则冻结。半托管价格字段为空仍需追溯规则来源；引用列表只暴露摘要，不得据列表没有值就断言引用没有配置。

2026-10-16 用户已明确视频三项共同规则：保留弹窗默认选中的全部图片，转场和音乐采用原生弹窗当次默认值，此规则取代上文对应历史缺项。必须先观察完整选中图片集合、实际转场值、音乐稳定标识及同次商品/会话绑定，再冻结；只看到 selected 标签或传入自报 observation 不构成来源。缺少可验证来源时继续拒绝，不能替换成首张、前 N 张、代码预设值或静音。三项规则不再待确认；尚未据此执行选择、生成或写回真实共同模板。

共享模板 `editor_actions.<categoryId>` 现可显式配置 video、wholesale、translation，沿用现有配置字段：所有键必须提供、enabled 必须为 true，视频 failure_strategy=pause，翻译 direction=zh_en 并完整覆盖 title/attributes/description_pc/description_mobile/custom_name。批发参数必须与固定/补差及最终解析的 bulkOrder/bulkDiscount/reduceStrategy 一致；不从 executor 默认值或商品独立配置补齐。动作进入同一个方案哈希和 SAVE1 payload，SAVE2 不重放主阶段动作。系统 Configure 已创建 v1.4.0 草稿并读回成功，但这些配置尚未全部接到生产动作和独立回执，不是执行放行证明。

首写前准备现通过 Path B 的独立 `PREPARE_ROLLBACK` command 接入：实际原值、稳定绑定、恢复可行性、截图及 task/job/scope/session/snapshot 权威一起持久化到现有证据表。首次 apply 在同一个 JavaScript 中比较真实原值，任何已尝试而未成功的填写不得自动重试；后续步骤只读核对已成功结果。`execution_path=B` 来自冻结 payload hash，不接受调用方额外 defaults 标记。该机制不自动 restore，也不表示跨类目或当前全部复杂控件已具备完整恢复能力。

批发新增独立零写验证命令 `validate_editor_wholesale`，复用严格字段读回，要求真实启用状态、百分比单位、共同参数和完整 SKU 关系；当前回执必须关联本次独立 command，并从 Runner 原结果核对首 FILL 来源。该映射尚未加入 active steps，不能单独运行它或以它替代视频→批发→翻译全顺序。视频/翻译新结果尚未贯通 SAVE1 的冻结预期值与 scope，因此仍禁止据当前局部检查释放真实保存；原 snapshot/preimage 不得就地重写。

主编辑 Adapter 与成功合同已共同消费完整冻结字段读回，不再依赖旧 `field_details/variant_rows` 形状。Path B 的新快照保留全部显式引用身份、原审计明细及字段最终 source/source_ref，并沿 SAVE1/SAVE2 原有 hash 传递；历史缺证保持缺失，不就地升级旧快照。字段值匹配只证明该项读回，不证明引用模板全部应用、海关分区完整或半托管全流程完成；缺失后置条件继续拒绝。冻结来源与实际模板作用范围必须可追溯，不能借未纳入 payload hash 的旧 Path A 上下文或重写 preimage 掩盖模板套用副作用。

当前源码已实现上述窄系统流的 scope、原子启动、Discovery seal、fresh Formal lineage 与 1+6 receipt 验收合同，并保持严格 fail-closed：Discovery 只允许一个 `FIRST_SAVE_INTENT` command/lease/ledger/native-handshake，在唯一 SAVE1 与独立未发布 VERIFY 后由仓储事务封存 receipt、停止 task，禁止 SAVE2/其它商品；GET 恢复从私有持久权威重建，而不是只信 summary boolean。Formal 在任何 CAS 前要求 fresh snapshot/task/scope/Approval 严格晚于 Discovery seal，绑定 predecessor/receipt，并要求 Discovery after 值与 Formal 首商品 SAVE1 preimage 完全一致。所有阶段必须显式复用上例同一个 `$evidenceDirectory` 与 `$attemptJournalFile`；首次创建 journal 使用独占 `CreateNew`，既有 journal、receipt 与 scope 只允许独占打开和全量复验。POST 已发送但无法证明未受理时一律记为 `UNKNOWN`，不得再试。

正式任务完成后，只能从 `GET /api/tasks/{task_id}/acceptance-export` 取得公开验收投影，再交给 `scripts/report/generate_v1_acceptance_record.py` 生成只保留 opaque refs/hash/status/count 的脱敏记录。生成器复验 sealed Discovery 的 1 次 SAVE1/5 个 leaf proof 与 fresh Formal 的 6 次独立 SAVE/30 个 leaf proof，要求 command/lease/proof 不复用、时间顺序和首商品 readback→preimage 连续、每次恰好一个 mutation、零发布、五项能力、writer fence、provenance、`UNKNOWN=0` 和自动重试为零；全部同源才输出 `REAL_PATH_B_3_ACCEPTED`。生成器只能复核公开投影内部一致性；证据来源真实性由 backend 从私有 DB/ledger/command/action-result/receipt 权威重建后负责。证据缺失时 `published` 保持 `null`，不得用“没有观察到发布”伪造 `false`。

## 5. 结果与证据

“保存结果”必须按 task → ordered job → product → action 展示：

- snapshot/hash、队列位置和运行身份；
- SAVE command、mutation ledger 与动作时间；
- 回包、页面成功态、独立未发布证明；
- 逐字段预期/读回；
- 视频、翻译、批发和 rollback preparation 的逐项 before/after 与读回；
- Path B 主编辑保存和半托管保存各自的 command、JIT/lease、ledger、业务回包与页面事实；
- `succeeded`、已知前置失败或 `UNKNOWN/needs_manual_review`；
- HVD、日志、API、SQLite 与报告的一致性。

没有五项 REQUIRED 能力证据、两段保存事实或完整三铁证的商品不得计入成功。旧报告、mock、HTML、手工截图或“未点发布”不能补齐证据。

## 7. 停止与现场保护

- 正常停止：关闭启动器/桌面窗口；有真实任务时先在 UI 安全停止并等待 worker ack。
- 视频生成、主编辑保存、半托管保存等外部 mutation 派发后进程异常：不要重启后自动重试，保留 ledger、日志和页面，状态应为 `UNKNOWN`。
- 首次外部 mutation 前失败：按冻结 rollback plan 逆序恢复页面并精确读回；恢复不完整同样停批。外部 mutation 已派发后不得用第二次写入冒充回滚。
- 不删除 `data/**`、SQLite、runtime lock、证据或日志来“解决”状态冲突。
- 不启动第二个同数据目录实例，不强占正在服务真实任务的 8000 端口。
- 不提交 Cookie、账号密码、token、raw 抓包、真实业务样例或诊断原文。
