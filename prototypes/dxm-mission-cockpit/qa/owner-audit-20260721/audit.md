## 步骤与健康度

1. **生产首页进入任务** — 阻塞
   - `05-production-home.png` 仍以“认领 → 单商品保存”为主流程，侧栏拆成 13 个入口。
   - 同一登录/阻断事实由顶部错误条、三张决策卡、右侧主卡和底部提示重复表达。

2. **批量编辑工作台** — 方向正确，需减噪
   - `01-edit-workbench.png` 的五项导航、两张准备卡、现场信任条和批次表更符合运营心智。
   - “未来目标 / 原型 / 当前生产 single_save”在顶部、横幅、卡片与页脚重复，应只保留一个动态能力状态入口。

3. **读取并冻结商品箱范围** — 交互清晰，能力未接通
   - `02-read-product-scope.png` 明确商品主数据留在店小秘，不提供本地商品或店铺选择器。
   - “模拟读取商品箱现场”会把真实页面与本地假成功混在一起，生产代码中必须禁止。

4. **整批一次批准** — 健康
   - `03-batch-approval.png` 把范围、顺序、模板、异常策略和批准摘要集中在一次确认中，主操作唯一。
   - 批准摘要必须由后端真实有序商品指纹生成，不能使用前端 `fnv32:prototype-*`。

5. **自动串行驾驶舱** — 信息层级可用，运行事实为模拟
   - `04-batch-complete.png` 的 `i/N`、成功、等待、隔离、UNKNOWN 和队列/当前件双栏值得移植。
   - “HUD 合同”“原型窗口可置前”“未来批次目标”等研发说明应移出运营首屏。

## 主要发现

### P0

- 生产主流程仍是旧的认领先行模式，与最新批量编辑产品方向相反。
- 原型的批次创建、批准、执行、UNKNOWN 和证据均由 fixture、localStorage 与定时器驱动，任何运行状态都不能直接移植。
- 批次能力必须由后端 capability 与服务端状态提供；未就绪时不得出现本地可成功的主操作。

### P1

- 侧栏收敛为：编辑工作台、模板中心、浏览器现场、批次记录、系统设置。
- 首页只保留一条动态状态、一个主操作、当前批次摘要和最近异常/批次。
- 批次创建保留四步：读取现场、冻结范围、锁定模板、整批批准。
- 批次驾驶舱首屏只展示当前 `i/N`、商品身份、Session、控制权、当前动作和异常；日志、端口、路径和证据细节进入抽屉。

### P2 / 可访问性风险

- 生产正文 12px、辅助文字存在 10px，桌面端长时间操作可读性不足；正文应提升到 14px，辅助信息不低于 12px。
- 原型步骤与单选/复选控件有可读标签，键盘语义基础良好；仍需在生产实现中验证完整键盘流、焦点恢复、错误后焦点和 200% 缩放。
- 仅凭截图不能证明颜色对比、屏幕阅读器播报或动态状态通知符合完整 WCAG 要求。

## 落地顺序

1. 先定义真实批次 capability、范围快照、批次计划、子任务结果和运行状态。
2. 再接生产 `App.tsx` 与五项导航；能力未就绪时 fail-closed。
3. 新建生产批量编辑页面，四步全部调用真实 API，禁止 fixture/localStorage fallback。
4. 把浏览器现场与记录页收敛到同一批次事实。
5. 最后调整 14px 字体基线、网格、队列和响应式，并做同视口设计 QA。
